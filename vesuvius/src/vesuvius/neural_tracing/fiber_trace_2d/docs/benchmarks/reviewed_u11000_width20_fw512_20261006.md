# Cumulative-width presence weighting — frozen raw u11000

Same reviewed91fibers/182directions and prefix512 terminal FW/BW20/40 protocol. Presence multiplier=max(0,1-abs(sample_width/mean_width-1)/0.20). Mean initialized from seed and updated by each newly irrevocable forward point, before its observer. Speculative beam samples never update it; shared-prefix commits can lag the frontier. Each reverse check freezes the accumulated forward mean, including its endpoint, with no reseeding/updating. Restart initializes a new mean. Invalid candidate widths suppress presence; invalid seed/committed widths raise an error.

Width is the shared annotation softplus output in network-input voxel units, explicitly published as float32 `fiber_width.ome.zarr` / manifest channel `width`. Same units used for both sides of each ratio. Existing BF16 inference and float16 accumulation retained; no scheduling or worker settings changed. Width-containing cache identity differs from legacy caches; those remain untouched. Auxiliary normal/HV heads not used.

Error restarts are80-base-voxel grouped episodes, filtered stops ungrouped. Actual stops counts all individual error+filtered events. Mean=retained GT mm/(actual stops+1). Median/P05/P95 use actual retained spans including terminal/zero-length spans. GT determines ordinary failure endpoints/reseeding, so terminal failure→filter conversions remain oracle-timed.
