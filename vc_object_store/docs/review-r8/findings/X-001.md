# X-001 — Joint-evaluation provenance requirement breaks the paired-neighbor producer

Confirmed by source comparison; introduced by `b0b68f351`. The documented `fiber_neighbor_pair` workflow creates `<output>/prepared/tensors.npz`, `gt_events.json` and `selection.json`, then passes that directory as `baseline_root` to `fiber_joint_gt_eval` (`fiber_neighbor_pair.py:42–50,59–66`, all workflow paths under `vesuvius/src/vesuvius/neural_tracing/fiber_trace_3d/`). Its separate `<output>/inputs.json` has only `selected_fibers`, not the source provenance joint assembly requires. On a fresh paired run with a valid GT summary, joint preparation now reads the never-produced `<output>/prepared/inputs.json` unconditionally (`fiber_joint_gt_eval.py:76–83`), and the joint subprocess fails before assembly. Prior to the change that producer's files met the joint consumer's baseline contract.

The same newly mandatory baseline file changes the direct CLI contract in `vesuvius/docs/fiber_workflows.md:64–69` and the split-search joint/selectable arms that forward `baseline_root` (`fiber_split_weight_search.py:154–157`). Separately, joint assembly now requires `gt_root/uv_whole/summary.json` with layout provenance instead of the documented `config.json` and tensors; the documented GT input can be assembled without a summary (as neighboring GT event fixture construction demonstrates). That is a compatibility/migration case distinct from the fresh paired producer failure. Report-only dispatch still branches before either new requirement.

Do not fix by stamping old tensors with a fresh digest. The active producer needs to validate and carry source evidence for the selected graph and emit the shared parent manifest with its prepared tensor output. Define a supported migration or actionable regeneration path for older baseline/GT artifacts, then exercise the producer-to-consumer seam, both split-search joint policies, and the direct documented invocation. No test was executed.
