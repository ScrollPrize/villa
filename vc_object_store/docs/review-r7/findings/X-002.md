# X-002 — Joint GT assembly pins its output, not the input geometry behind its tensors

Source-confirmed pre-existing omission relative to `1b32f031b`; R6 changes only the downstream reads. In `vesuvius/src/vesuvius/neural_tracing/fiber_trace_3d/fiber_joint_gt_eval.py::run`, saved baseline and GT graph tensors supply arc bounds and events (70–72). The input signature hashes the baseline/GT tensor files and the *current GT store* digest, but not the baseline fiber store (73–75). When creating the combined store, both input reads are live, not tied to those saved tensors or even the sampled GT digest (78–82). On a retry, an existing combined store is accepted without a persisted source check. The new source version at 85 then correctly protects split and sampling against changes to that combined store **after** it is opened; it cannot detect the earlier mismatch.

For the fresh path, edit a baseline fiber without changing its UUID or breaking arc bounds after baseline tensors are produced. Joint assembly can then write the changed geometry and use it with older arcs. A GT edit between digest and first geometry read has the same issue inside one invocation. In contrast, selected-dataset assembly checks the subset coordinates against source geometry before splitting. Exercise both parent stores, a fresh/reused combined store, and a publication after the combined pin as a control. No test was executed.
