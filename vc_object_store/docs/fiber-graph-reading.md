# Reading large fiber graphs

`readCompactFiberConstraintGraph(collection, transaction, workers)` is the numeric workflow reader for core schema 22 and compact measurement format 4. It projects binary edge/endpoint UUIDs, float32 arc positions, decoded endpoint normals, the canonical A-to-B unit connector, one quantized winding distance and the parallel/perpendicular kind. Validity comes from the compact direction sign bytes. It does not load tags, metadata JSON, dependency descriptors, history or complete extension rows. UUIDs stay binary in native memory. The default is 32 workers.

The collection pins its physical connections before dispatch. Each connection is scanned by only one worker; collection calls must not run concurrently on that transaction. Shards and referenced stores use the same collection snapshots and UUID routing metadata. Overlay precedence and endpoint lifecycle resolve the winning measurement rows. Endpoints and measurements use the canonical core UUID order; there is no source-reversal field. The reader validates exact BLOB sizes, codec values and endpoint identities, and explicitly rejects older measurement formats rather than silently treating them as format 4.

Endpoint lookup indexes use per-partition memory arenas and are released before final assembly. The final graph is sorted by edge UUID and receives dense runtime indices from zero to the row count minus one. These indices are not persistent identities; source event IDs are neither stored nor reconstructed. The optional progress callback reports endpoint scanning, measurement scanning, overlay resolution, index release and completion.

The measurement format intentionally quantizes arcs to little-endian float32, normals/connectors to the shared three-byte Lasagna encoding and winding distances to sixteenths of a turn. Distances above 15.875 turns are skipped before rounding. See [the extension schema](extensions.md#fiber-graph-solve-extension). Source measurement XYZ and evidence weights are not persisted. Access to stored XYZ fails explicitly; the connector is a unit direction, not a replacement for physical endpoint coordinates or connector length. Consumers explicitly needing geometry must evaluate source fibers separately at their arcs.

For publishing modified measurements, prepare `prepareFiberConstraintMeasurementScan` on the transaction-owning thread and invoke its returned job while that transaction remains alive. It streams winning original rows in bounded batches to a concurrent visitor. This preserves unrelated fields without retaining the complete extension table. The normal-alignment writer feeds those batches into bounded UUID-sharded queues.

The rich `readFiberConstraintGraph` API remains available for consumers explicitly requesting full records. Large numeric workflows and Python `fiber_constraints()` use the compact reader instead. The latter still formats UUID strings for its existing Python API; its conversion time is separate from the native read benchmark.

Build with `-DVC_OBJECT_STORE_BUILD_BENCHMARKS=ON`, then run `vc_bench_fiber_graph_read STORE WORKERS`. It opens the input read-only and reports elapsed phase times and final numeric payload size. Use an external timeout for bounded pilots. `object_store_fiber_constraint_graph` tests agreement with the rich reader for compact format 4 on plain/packed shards, overlays, streaming row preservation and deleted relations, and checks explicit rejection of legacy format 3. `compact_fiber_measurements` tests exact codec bytes, equatorial normals, distance limits and the minimal core-edge layout.
