# Native AFV import and v2 validation

Geometry and relation imports use the source-independent [`importInitialCollection`](initial-import.md) API by default. The library owns independent shard connections, initial object/geometry construction, relation streams, transactions, sealing, linking and atomic publication. This command supplies source decoding and progress/profiling. Explicit `verify_readback:true` additionally enables diagnostic readback; it is off by default. Initial construction preserves the native v2 schema; it is not an alternative reduced data format. Performance reports distinguish source decoding, native insertion, verification and final persistence. The former editing-API comparison paths have been removed; `initial_batch:false` is rejected. Ordinary interactive imports/edits use the regular store APIs, not shard assembly.

`vc_object_import_afv CONFIG.json` streams an AFV v1 snapshot into a new, sealed, history-off, spatial-index-free v2 store. It uses the same native `AfvSource` decoder as the Python AFV workflow. The input is read-only; records are processed in bounded batches, and failure removes the private sibling staging directory. Publication refuses an existing destination. The source dataset namespace plus the original fiber ID determines each object UUID, so identities are unchanged by batching or path relocation.

The streaming adapter derives stable entity UUIDs in parallel source readers, then dispatches bounded batches to `uuidShardIndex(uuid, shards)`. Object and edge records use the same UUID-hash routing contract as the native batch API; source numeric IDs remain provenance only. No full-dataset preprocessing or per-object routing directory is required.

```json
{
  "source": "/datasets/fibers.afv",
  "output": "/scratch/fibers.vcobj",
  "volume_id": "catalog-volume-id",
  "batch_size": 256,
  "batch_bytes": 67108864,
  "fiber_limit": 1000,
  "report": "/scratch/import-report.json"
}
```

Build the `vc_object_import_afv` target in a normal vc_object_store CMake build (`VC_OBJECT_STORE_BUILD_TOOLS=ON` or `VC_OBJECT_STORE_BUILD_TESTS=ON`). Start with a finite pilot; set `fiber_limit` to zero for the entire source. `volume_id` is the actual catalog volume identifier, not a newly generated UUID. Alternatively specify `unbound:true`. `scale_factor` defaults to 1 and records the coordinate binding without transforming samples.

Every original float64 XYZ byte is retained in `line_points`. Both the native importer and Python `scripts/import_afv.py` declare empty control arrays, with no invented control points or IDs. This changes the older Python AFV import's synthetic endpoint-control behavior; actual control points in other input formats are unaffected. The fiber name, family, point count, length, bounds and annotations are preserved; collection metadata is stored once.

Optionally add `"constraints":"/datasets/constraints.afc.sqlite"` to import the associated integer-ID AFV constraint database, with one edge per original constraint. Its declared AFV UUID must match. The stable source constraint UUID is its native edge UUID: independent observations of the same pair remain separate without inventing geometry dependencies or per-observation edge kinds. For a fiber-limited pilot, only edges between imported fibers are eligible; `constraint_limit` selects a prefix of eligible edges ordered by source ID, and zero means all eligible edges. Neither input is changed. Reports separately count/timestamp edges and mark whether constraints were imported. A geometry-only run reports `constraints_imported:false` and does not claim to be a complete winding-solver dataset. Newer AFC files with UUID object endpoints do not need AFV ID translation and are intentionally rejected by this adapter. Unknown constraint columns are rejected rather than silently dropped.

The decoder validates format/version, completeness, native-coordinate declarations, block ordering, identical shared block endpoints, catalog point counts, finite coordinates and bounds. Full scans also validate collection totals. Import reports separate source decoding, store ingestion, sealing and final persistence. With `verify_readback:true`, every imported fiber is additionally read back and compared exactly; this diagnostic is timed separately and is not part of normal import. Extrapolations are labeled estimates and exclude readback time. A prefix pilot can have a different length distribution than the full volume, so report exact full-volume measurements when available.

`source_open_seconds` measures initial source opening; `end_to_end_seconds` includes that setup, the import pipeline, final export and optional validation. Subtract `validation_seconds` for normal import latency. The older `total_seconds` starts inside the pipeline after opening the source. `source_read_seconds` and `constraint_source_read_seconds` are reader-worker preparation sums, excluding queue push time; they overlap and must not be added to ingestion wall time. The prepared-input benchmark offers an explicit [matched AFV-record mode](../benchmarks/README.md) for comparing this adapter against the same native import API with records already in RAM.

## Shards and packed containers

Set `shards` to the writer count (1–256). Each independent SQLite writer receives UUID-routed batches, owns disjoint numeric ID reservations, performs one bulk transaction and seals at the same generation. Object UUIDs remain identical to the unsharded import. Numeric row IDs are internal and can differ with reader scheduling; they are not source identities. Every import receives a fresh logical store UUID shared by its shards. Without packing, multiple shards produce a directory containing `collection.vcobj` and its shard files.

`readers` controls parallel source readers (default min(shards, 8)). Readers scan disjoint source-ID intervals, derive UUIDs, and dispatch to shard queues. `batch_size` bounds rows per destination batch; `batch_bytes` (default 8 MiB) bounds each reader’s aggregate pending payload before flushing. `queue_bytes` (default 256 MiB) is split across destination queues for each of the object and edge streams; both can briefly coexist while the last objects drain. A single oversize batch per destination is allowed to ensure progress; SQLite caches, active consumer batches and source-reader buffers are additional memory. Object readers finish before edge readers start, but writers need not finish their object insertion together. Waiting producers poll cancellation so failures cannot strand queue workers.

Add `packed:true` to create those independent databases directly through the packed VFS and publish one compact container at `output`. `resident_bytes` controls the packed writer cache (default 256 MiB); SQLite worker caches and active fibers are additional memory. Packed bulk writes are disposable until finalization, which durably publishes the container. A single uncompressed shard publishes an ordinary SQLite file; multiple uncompressed shards publish a directory. Combined geometry/AFC import supports all shard counts; separate relation-only overlays remain optional. Finishing the batch writes routing metadata from worker-owned descriptors, closes the writers and completes persistence/atomic exposure. It does not reopen the shards or the collection. Optional `verify_readback:true` reads through the composed collection and checks every imported fiber’s bytes/metadata and every relation’s endpoints/anchors/metadata. It is not part of normal ingestion. Reports separate pipeline wall time (including queue backpressure), native worker times, ingestion wall time, persistence and optional validation; overlapping worker timings must not be summed into wall time.

## Parallel relation-only overlays

After importing geometry, supply `geometry_collection` (the published collection manifest or packed container), `constraints`, and `shards` to import independent relation shards. `source` still identifies the original AFV namespace. `output` is a new directory, or a new single container with `packed:true`. Each worker links the sealed geometry collection, stores only its own native edges with original endpoint UUIDs, and seals independently; the final manifest composes those stores. Geometry is not copied. `constraint_limit` selects an explicit prefix for a pilot; zero imports the full AFC source. Readers scan contiguous constraint ID intervals, then dispatch each edge by its derived UUID; these read intervals do not determine destination placement. If `verify_readback:true` is requested, diagnostic readback resolves original endpoint UUIDs, compares all anchors and metadata, and checks representative linked fiber geometry. Normal imports do not perform these reads.

`initial_batch:true` (default) uses `ObjectCollection::importInitialEdges`. The destination must be history-off and have no edges yet. The producer fills batches (`batch_size`, default 1024), with endpoint UUIDs (plus optional routing hints) and ordinary `EdgeRecord` values; it may read source data but must not mutate or commit the destination. A savepoint covers the complete stream, including allocated IDs and index changes. Exceptions roll back the stream, allowing a corrected retry in the outer transaction. Publication timestamps and ID reservations are shared within a batch. Trusted batch input skips endpoint existence/lifecycle/geometry lookups and cross-table identity scans; record-format checks and SQLite uniqueness/applicable foreign keys remain active. The producer is responsible for reference consistency. No endpoint directory or cache is built. Known nonunique lookup indexes are rebuilt at the end (`defer_indexes:true`); extension and uniqueness indexes are never removed. There is no alternate per-edge editing path in this batch command.

For ingestion without foreground payload disk writes, combine `packed:true`, `memory_first:true` and `background_flush:false`, with a sufficient `resident_bytes` budget. This is disposable bulk construction: it does not promise durability before successful finalization. Exceeding the resident budget fails the import rather than silently evicting to disk. SQLite caches and source batches consume additional memory. Finalization writes the compact container directly from retained RAM and durably publishes it; `persistence_seconds` measures this separately. `background_flush:true` permits background writeback while retaining strict memory-first residency. The ordinary bounded-cache VFS mode remains available with `memory_first:false` and can block on eviction I/O. None of these options changes the native records or permits publication of a partial import.

For an explicit allocator-contention comparison, `sqlite_memory_statistics:false` disables SQLite's global memory accounting before any SQLite initialization in this executable. It does not change production `ObjectStore` defaults, transaction semantics, or stored values. Keep the setting in the recorded local benchmark config when comparing runs; process peak RSS remains reported independently of SQLite accounting.

`sqlite_pagecache_bulk_bytes` optionally asks SQLite to allocate an initial page-cache block per connection rather than allocate each page separately after its small default block is exhausted. Zero preserves SQLite's default. This uses `SQLITE_CONFIG_PAGECACHE` with a null buffer and a negative KiB count, not a shared global memory pool. It can reduce the global page allocator's mutex traffic, but increases memory reservations for all connections in this executable, including source and linked-store readers. It is an explicit standalone startup setting, not a production library default. Record its value and peak RSS when benchmarking; it does not change the page-cache size limit selected by `sqlite_cache_bytes` or the packed VFS budget.

`sqlite_cache_bytes` configures the SQLite page cache per connection, including readonly linked-store connections. The unchanged default is 8,192,000 bytes (`cache_size=-8000`). Large randomly accessed relationship imports can benefit from a larger budget, for example 134,217,728 bytes, but the possible total multiplies by the worker count, linked stores and connection pools. This setting is independent of the packed VFS's `resident_bytes` and native geometry caches; it is available to C++ callers as `OpenOptions::sqliteCacheBytes`. The report records the selected budget and measured process RSS.

For relation-import profiling, `profile:true` adds per-worker exclusive native phase timings to the final report. Periodic progress records show aggregate fiber/constraint counts and elapsed time; source-pipeline wall time includes queue backpressure and overlaps insertion. Phase timings include waits, are opt-in, and must not be interpreted as CPU samples. Progress counts describe work attempted before transaction publication, not a validated completed import. Use short, externally time-limited trials for slow full-ID-range workloads and report extrapolated ingestion time separately from commit, readback and publication. Prefix-only pilots may miss the full graph's larger endpoint working set.

For standalone SQLite contention diagnostics, additionally set `profile_sqlite_mutex:true`. Before initializing SQLite, the executable installs a forwarding overlay around its original mutex methods; no locks are removed. Each worker reports its own entry counts and one-in-1024 sampled entry latency for each static SQLite mutex category, plus an aggregate for dynamic/unrecognized mutexes. These are entry latencies, including uncontended overhead, not lock-hold durations; estimated totals extrapolate sampled observations. The optional profiler adds overhead and is not a production library setting or a substitute for an uninstrumented throughput comparison.

On Linux/macOS builds with `execinfo` and `dladdr`, `profile_sqlite_stacks:true` additionally samples a PMEM caller stack every 65,536 entries. At most 32 distinct eight-frame stacks are retained per thread; excess distinct samples are counted. Capture happens before acquiring the lock, symbol resolution only when reporting progress. This requires mutex profiling and is disabled by default; stripped libraries may expose addresses rather than all function names.

The current edge schema has native endpoint identities and anchor positions/directions. AFC arc offsets, normals, winding distances, parallel/perpendicular scores, evidence weights and diagnostic measurements do not yet have native typed columns: this adapter preserves them as parsed values under `meta.afc`, including explicit original endpoint identities so canonical endpoint reordering cannot reverse their meaning. Normals are not mislabeled as fiber-tangent directions. Collection-level AFC metadata is stored once. Optional `verify_readback:true` checks every imported edge with its exact anchor positions, endpoint identities and full metadata; reports separate metadata JSON bytes from geometry bytes. One source constraint remains one edge, with no pair bundling or silent attribute dropping.
