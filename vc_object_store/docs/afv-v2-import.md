# Native AFV import and v2 validation

Geometry and relation imports use the source-independent [`importInitialCollection`](initial-import.md) API by default. The library owns independent shard connections, initial object/geometry construction, relation streams, transactions, sealing, linking and atomic publication. This command supplies source decoding, progress/profiling and benchmark readback only. Initial construction preserves the native v2 schema; it is not an alternative reduced data format. Performance reports distinguish source decoding, native insertion, verification and final persistence. Explicit `initial_batch:false` retains the former editing-API implementation only for comparison.

`vc_object_import_afv CONFIG.json` streams an AFV v1 snapshot into a new, sealed, history-off, spatial-index-free v2 store. It uses the same native `AfvSource` decoder as the Python AFV workflow. The input is read-only; records are processed in bounded batches, and failure removes the private sibling staging directory. Publication refuses an existing destination. The source dataset namespace plus the original fiber ID determines each object UUID, so identities are unchanged by batching or path relocation.

```json
{
  "source": "/datasets/fibers.afv",
  "output": "/scratch/fibers.vcobj",
  "volume_id": "catalog-volume-id",
  "batch_size": 256,
  "batch_bytes": 67108864,
  "fiber_limit": 1000,
  "report": "/scratch/import-report.json"
}
```

Build the `vc_object_import_afv` target in a normal vc_object_store CMake build (`VC_OBJECT_STORE_BUILD_TOOLS=ON` or `VC_OBJECT_STORE_BUILD_TESTS=ON`). Start with a finite pilot; set `fiber_limit` to zero for the entire source. `volume_id` is the actual catalog volume identifier, not a newly generated UUID. Alternatively specify `unbound:true`. `scale_factor` defaults to 1 and records the coordinate binding without transforming samples.

Every original float64 XYZ byte is retained in `line_points`. Both the native importer and Python `scripts/import_afv.py` declare empty control arrays, with no invented control points or IDs. This changes the older Python AFV import's synthetic endpoint-control behavior; actual control points in other input formats are unaffected. The fiber name, family, point count, length, bounds and annotations are preserved; collection metadata is stored once.

Optionally add `"constraints":"/datasets/constraints.afc.sqlite"` to import the associated integer-ID AFV constraint database, with one edge per original constraint. Its declared AFV UUID must match. The stable source constraint UUID is also its native `relation_key`: independent observations of the same pair remain separate without inventing geometry dependencies or per-observation edge kinds. For a fiber-limited pilot, only edges between imported fibers are eligible; `constraint_limit` optionally limits their count, and zero means all eligible edges. Neither input is changed. Reports separately count/timestamp edges and mark whether constraints were imported. A geometry-only run explicitly reports `constraints_imported:false` and does not claim to be a complete winding-solver dataset. Newer AFC files with UUID object endpoints do not need AFV ID translation and are intentionally rejected by this adapter. Unknown constraint columns are rejected rather than silently dropped.

The decoder validates format/version, completeness, native-coordinate declarations, block ordering, identical shared block endpoints, catalog point counts, finite coordinates and bounds. Full scans also validate collection totals. Import reports separate source decoding, store ingestion, sealing and full exact-byte geometry readback. Each imported fiber is read back, not just a sample. Extrapolations are labeled estimates and exclude readback time. A prefix pilot can have a different length distribution than the full volume, so report exact full-volume measurements when available.

## Shards and packed containers

Set `shards` to a positive worker count (maximum 256) to partition a geometry import by balanced contiguous source-ID intervals. Each worker has an independent source reader and SQLite store, performs one bulk transaction and seals at the same generation. Object UUIDs remain identical to the unsharded import. Every independently created import gets a fresh logical store UUID shared by its shards; the source AFV UUID is provenance, not the publication identity. This prevents a prefix pilot and a full import with different contents from satisfying the same dependency pin. Explicit numeric object IDs are original AFV IDs plus 2, with ID 1 reserved for collection metadata; range reservations prevent collisions. The published readonly `ObjectCollection` routes across the physical stores. Without packing, `output` is a new directory containing `collection.vcobj` and its shard files.

Add `packed:true` to create those independent databases directly through the packed VFS and publish one compact container at `output`. `resident_bytes` controls the packed writer cache (default 256 MiB); SQLite worker caches and active fibers are additional memory. Packed bulk writes are disposable until finalization, which durably publishes the container. A single uncompressed shard publishes an ordinary SQLite file; multiple uncompressed shards publish a directory. Combined geometry/AFC import requires one shard; use the separate relation-sharded workflow below for larger graphs. Every shard's geometry is checked byte-for-byte and fiber metadata by value, in parallel through its published physical store; the full collection additionally verifies numeric and geometry routing at each shard boundary. Reports include per-shard timings, aggregate wall time, publication/export time and peak resident process memory (Linux/macOS). Source/native/seal durations are worker sums, while ingestion/total are wall-clock durations. Checkpoint/close work is included in library ingestion timing rather than reported as a fabricated independent measurement.

## Parallel relation-only overlays

After importing geometry, supply `geometry_collection` (the published collection manifest or packed container), `constraints`, and `shards` to import independent relation shards. `source` still identifies the original AFV namespace. `output` is a new directory, or a new single container with `packed:true`. Each worker links the sealed geometry collection, stores only lightweight endpoint references and its own native edges, and seals independently; the final manifest composes those stores. Geometry is not copied. `constraint_limit` selects an explicit prefix for a pilot; zero imports the full AFC source. Partitioning uses contiguous constraint ID ranges and checks the aggregate row count. Readback resolves qualified original endpoint identities through the collection API and compares all anchors and metadata. After publication, a representative edge in every shard is resolved again together with its externally linked fiber geometry.

`initial_batch:true` (default) uses `ObjectCollection::importInitialEdges`. The destination must be history-off and have no edges yet. The producer fills batches (`batch_size`, default 1024), with qualified endpoint keys and ordinary `EdgeRecord` values; it may read source data but must not mutate or commit the destination. A savepoint covers the complete stream, including endpoint references, allocated IDs and index changes. Exceptions roll back the stream, allowing a corrected retry in the outer transaction. Publication timestamps and ID reservations are shared within a batch. Native validation, unique constraints, foreign keys and current-endpoint lifecycle/geometry checks remain active; no duplicate permanent binding records are written. Known nonunique lookup indexes are rebuilt at the end (`defer_indexes:true`); extension and uniqueness indexes are never removed. `endpoint_cache_entries` (default 65536) bounds each endpoint lookup cache. Explicit `initial_batch:false` retains the ordinary per-edge editing path for parity and performance comparisons.

For ingestion without foreground payload disk writes, combine `packed:true`, `memory_first:true` and `background_flush:false`, with a sufficient `resident_bytes` budget. This is disposable bulk construction: it does not promise durability before successful finalization. Exceeding the resident budget fails the import rather than silently evicting to disk. SQLite caches, source batches and endpoint caches consume additional memory. Finalization writes the compact container directly from retained RAM and durably publishes it; `persistence_seconds` measures this separately. `background_flush:true` permits background writeback while retaining strict memory-first residency. The ordinary bounded-cache VFS mode remains available with `memory_first:false` and can block on eviction I/O. None of these options changes the native records or permits publication of a partial import.

For an explicit allocator-contention comparison, `sqlite_memory_statistics:false` disables SQLite's global memory accounting before any SQLite initialization in this executable. It does not change production `ObjectStore` defaults, transaction semantics, or stored values. Keep the setting in the recorded local benchmark config when comparing runs; process peak RSS remains reported independently of SQLite accounting.

`sqlite_pagecache_bulk_bytes` optionally asks SQLite to allocate an initial page-cache block per connection rather than allocate each page separately after its small default block is exhausted. Zero preserves SQLite's default. This uses `SQLITE_CONFIG_PAGECACHE` with a null buffer and a negative KiB count, not a shared global memory pool. It can reduce the global page allocator's mutex traffic, but increases memory reservations for all connections in this executable, including source and linked-store readers. It is an explicit standalone startup setting, not a production library default. Record its value and peak RSS when benchmarking; it does not change the page-cache size limit selected by `sqlite_cache_bytes` or the packed VFS budget.

`sqlite_cache_bytes` configures the SQLite page cache per connection, including readonly linked-store connections. The unchanged default is 8,192,000 bytes (`cache_size=-8000`). Large randomly accessed relationship imports can benefit from a larger budget, for example 134,217,728 bytes, but the possible total multiplies by the worker count, linked stores and connection pools. This setting is independent of the packed VFS's `resident_bytes` and native geometry caches; it is available to C++ callers as `OpenOptions::sqliteCacheBytes`. The report records the selected budget and measured process RSS.

For relation-import profiling, `profile:true` adds per-worker source decoding, native insertion and exclusive phase timings to the progress records. Phase timings include waits, are opt-in, and must not be interpreted as CPU samples. Progress counts describe work attempted before transaction publication, not a validated completed import. Use short, externally time-limited trials for slow full-ID-range workloads and report extrapolated ingestion time separately from commit, readback and publication. Prefix-only pilots may miss the full graph's larger endpoint working set.

For standalone SQLite contention diagnostics, additionally set `profile_sqlite_mutex:true`. Before initializing SQLite, the executable installs a forwarding overlay around its original mutex methods; no locks are removed. Each worker reports its own entry counts and one-in-1024 sampled entry latency for each static SQLite mutex category, plus an aggregate for dynamic/unrecognized mutexes. These are entry latencies, including uncontended overhead, not lock-hold durations; estimated totals extrapolate sampled observations. The optional profiler adds overhead and is not a production library setting or a substitute for an uninstrumented throughput comparison.

On Linux/macOS builds with `execinfo` and `dladdr`, `profile_sqlite_stacks:true` additionally samples a PMEM caller stack every 65,536 entries. At most 32 distinct eight-frame stacks are retained per thread; excess distinct samples are counted. Capture happens before acquiring the lock, symbol resolution only when reporting progress. This requires mutex profiling and is disabled by default; stripped libraries may expose addresses rather than all function names.

The current edge schema has native endpoint identities and anchor positions/directions. AFC arc offsets, normals, winding distances, parallel/perpendicular scores, evidence weights and diagnostic measurements do not yet have native typed columns: this adapter preserves them as parsed values under `meta.afc`, including explicit original endpoint identities so canonical endpoint reordering cannot reverse their meaning. Normals are not mislabeled as fiber-tangent directions. Collection-level AFC metadata is stored once. Every imported edge is read back with its exact anchor positions, endpoint identities and full metadata; reports separate metadata JSON bytes from geometry bytes. One source constraint remains one edge, with no pair bundling or silent attribute dropping.
