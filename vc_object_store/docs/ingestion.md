# Ingestion

Ingestion imports geometry files into a store once. After ingestion the
source files are no longer read: queries, edits, detection, and export all use
stored revisions. Re-importing an existing identity — even unchanged, even
retired — is an error, so later changes go through the store's
[editing](editing.md) APIs, and files are regenerated by
[export](writing.md#export). Every ingest returns a report
(`GeometryIngestReport`; a dict from Python); **always inspect `problems`**.

## The report

`ingested` and `edges_imported` count what was committed; `problems` lists
each failure; `uuids` are the objects created, in commit order; `existing`
lists identities the store already had (including retired objects; a
rejected fiber or collection batch lists every clash); `cancelled` is set when
a session ingestion stopped early on its cancel flag or a detach; and
`fatal_error` is described below. By default every failure is a problem and
ingestion continues as far as it can. With
`SourceIngestOptions::stopOnInfrastructureError`, a failure that is not the
source's own (store access, a failed commit, an unexpected exception) stops
ingestion and is reported as `fatalError` with the objects committed before
it; invalid sources, coordinate conflicts, existing identities and the store
changing underneath remain problems (`GeometrySourceRejected` in C++).
`SourceIngestOptions::requireSourceUuids` turns the file-name identity of a
UUID-less fiber into a problem, so such files need a UUID namespace.

## From files: `ingest_geometry_source`

```python
report = store.ingest_geometry_source(
    kind, source,
    coordinate_context={"volume_uuid": "20260411134726", "scale_factor": 1},
    tags=["initial_import"],
)
```

| Form | Signature |
| --- | --- |
| Python | `store.ingest_geometry_source(kind, source, coordinate_context=None, tags=None, uuid_namespace=None)` |
| C++ | `vc::objects::ingestGeometrySource(db, kind, source, progress, coordinateContext, tags, options)` in [objects/GeometryIngest.hpp](../include/vc_object_store/objects/GeometryIngest.hpp); a session overload ingests into any writable attachment (local or hosted) and also takes a cancel flag |
| CLI | `vc_object_ingest --db DB --author NAME --surface/--fiber/--point-collections/--tracks/--umbilicus SRC [--tag NAME ...] [--derive-uuids NAMESPACE]` |

`kind` is the object's geometry kind. What each accepts:

| Kind | Source | Commit unit |
| --- | --- | --- |
| `surface` | A tifxyz directory, or a folder of tifxyz directories | Per surface — one broken surface is reported, the rest still import |
| `fiber` | A fiber JSON, a fiber collection JSON, or a directory of fiber JSONs (linked files are loaded recursively) | Atomically — the whole batch, or nothing |
| `point_collection` | A `vc_pointcollections` JSON document | Atomically |
| `track` | A `.vctracks` packed directory, or a DBM path with an existing packed mirror | Per track — partial success is reported in `problems` |
| `umbilicus` | A `vc_umbilicus` JSON | Single object |

Rules that apply to all kinds:

- Existing UUIDs (including retired objects), duplicate UUIDs within a batch,
  and source links whose targets are missing or ambiguous fail the batch.
- `tags` (CLI `--tag`, repeatable) are added to every imported object,
  alongside any the source declares.
- `coordinate_context` supplies `{volume_uuid, scale_factor}` — see
  [volume identity](transforms.md#volume-identity-and-coordinate-scale). It
  fills unknown declarations and rejects source conflicts. XYZ payloads are
  never rescaled.
- Geometry, metadata, and the relationships the source declares (fiber
  branches, point and winding links) publish together. See
  [edges imported from sources](graph-edges.md#edges-imported-from-sources).
- Track identity is `(dataset_ref, external_key)`, not the file path.
- Import summaries (counts, lengths, dimensions, boxes) are snapshots of the
  imported state. After later edits, use geometry descriptors and spatial
  queries instead ([reading](reading.md)).

### Surfaces and channels

A tifxyz directory contributes `points` (float32 XYZ) plus its sidecar
channels. `mask.tif` page 0 becomes the `valid` channel: a vertex stays valid
only when every mask pixel it covers is at least 255, and a mask that is not a
whole multiple of the grid is rejected. Each other lowercase `.tif`/`.tiff`
sidecar becomes a channel named by its stem, aligned when each dimension is a
whole multiple of the grid (for example ink at 20 pixels per grid step).
Reserved or duplicate names, unaligned shapes, and unsupported layouts fail
before publication. Channel samples are stored exactly — no color conversion,
rescaling, or alpha handling. Adding a channel to an already-stored surface
is an [edit](editing.md#surface-channels): CLI
`vc_object_ingest --surface-channel UUID NAME TIFF`.

### Fibers

Fiber JSON version 4 is the transfer format. File import also accepts VC3D
version 1 and 3 fibers and version 1 fiber collections, storing them as
version 4:

- Version-4 branch endpoints require `target_uuid`; `branch_file` only
  locates a missing peer's transport file. Version-3 links resolve by
  `branch_file`. There is no filename-based endpoint repair.
- A link declared from both ends imports once. Reciprocal declarations that
  disagree roll back the whole batch.
- A level-0 open-data coordinate space becomes the volume binding
  (`meta.coordinates`), checked against `coordinate_context` when given.
- Version 1 control points are bare XYZ arrays; a missing `optimization_mode`
  reads as `lasagna`.
- A fiber without a `uuid` gets a name-based (version 5) UUID derived from
  its file name, so separate imports of the same file agree on its identity.

### Sources without UUIDs

Files written before objects carried UUIDs (VC3D tifxyz surfaces, whose `uuid` is
their directory name; PCL collections; version-1/3 fibers) can receive dataset
identities when a UUID namespace is supplied: `vc_object_ingest --derive-uuids NAMESPACE`,
`ingest_geometry_source(..., uuid_namespace=NAMESPACE)`, or VC3D's Import from Folder
dialog. Each such source then gets `uuid5(NAMESPACE, "<kind>:<key>")`, matching
Python's `uuid.uuid5`:

| Kind | Key |
| --- | --- |
| `patch` (surfaces) | `meta.json` `uuid` string, else the directory name |
| `fiber` | file stem; version-3 `branch_file` targets resolve the same way |
| `point_collection` | `<document stem>:<collection id>` |

Without a namespace, UUID-less fibers retain the default fixed-namespace
`vc3d_fiber/<filename>` identity; surfaces and PCLs still require canonical UUIDs.

The object records `meta.source.uuid_derivation = {namespace, name}`. Canonical
source UUIDs are kept, and tracks keep their `(dataset_ref, external_key)`
identity. Use one namespace per dataset; the same files then always map to the
same identities, so a repeated import fails as an existing identity rather than
duplicating objects. Keys do not depend on absolute paths, but renaming a file or
directory changes its identity.

### Point collections

PCL source links use document-scoped collection/point identities. The
namespace is `meta.source.origin`, the absolute lexically normalized import
path: symlink aliases and moved files are different namespaces, and only new
collections at the same path extend a document. Only active owners resolve
links; duplicate active identities fail. Point annotations in the source are
consumed into the first geometry revision and follow stable point IDs from
then on.

## From placeholders: `ingest_registered_geometry`

`store.ingest_registered_geometry(object_uuids=[...])` loads geometry into
object records that were created ahead of time. A placeholder is eligible only
if it has **no geometry history**; unrelated metadata it carries is preserved.
Use [edits](editing.md) for anything that already has geometry.

A surface placeholder with `storage_kind="url"` and an `http(s)://` or
`s3://` (public bucket) `storage_ref` is a remote tifxyz: ingestion downloads
`meta.json`, `x/y/z.tif` and any `mask.tif` once and stores them like a local
directory.

```python
remote = store.upsert_object({"kind": "surface", "name": "catalog",
                              "storage_kind": "url",
                              "storage_ref": "https://.../segment.tifxyz/"})
report = store.ingest_registered_geometry(object_uuids=[remote])
```

The placeholder, not the remote `meta.json`, supplies the object's identity.
Open Data catalog surfaces need no placeholder at all: a session fetches their
geometry on read through a registered fetcher (see
[sessions](hosted.md#sessions-objectstoresession)).

## From decoded objects (C++)

Pipelines that already hold decoded geometry skip file decoding:

- `prepareGeometrySource(kind, path, availableUuids)` decodes a native source
  outside any transaction, recursing into linked documents. `availableUuids`
  are existing endpoints whose stored contents stay authoritative.
- `ingestGeometryBatch(db, txn, batch, coordinateContext)` inserts a prepared
  batch in the caller's transaction. Duplicate, existing, and retired
  identities throw `std::invalid_argument`; this is not a refresh operation.
- `addIngestOperation(request, reader, batch, coordinateContext)` is the
  checked-request form (an `IngestGeometryOp`): every new object is expected
  absent, every existing fiber a branch links to is expected at its current
  version, and point/winding links must resolve within the batch.
  `ingestGeometrySource` submits exactly these requests — one per surface or
  track, one for a fiber or point-collection source.
