# Native AFV import and validation

Geometry and relation imports use the source-independent [`importInitialCollection`](initial-import.md) API by default. The library owns independent shard connections, initial object/geometry construction, relation streams, transactions, sealing, store_references and atomic publication. This command supplies source decoding and progress/profiling. Explicit `verify_readback:true` additionally enables diagnostic readback; it is off by default. Initial construction preserves native schema 21; it is not an alternative reduced data format. Performance reports distinguish source decoding, native insertion, verification and final persistence. The former editing-API comparison paths have been removed; `initial_batch:false` is rejected. Ordinary interactive imports/edits use the regular store APIs, not shard assembly.

`vc_object_import_afv CONFIG.json` streams an AFV v1 snapshot into a new, sealed, history-off, spatial-index-free schema-21 store. It uses the same native `AfvSource` decoder as the Python AFV workflow. The input is read-only; records are processed in bounded batches, and failure removes the private sibling staging directory. Publication refuses an existing destination. The source dataset namespace plus the original fiber ID determines each object UUID, so identities are unchanged by batching or path relocation.

The streaming adapter derives stable entity UUIDs in parallel source readers, then dispatches bounded batches to `uuidShardIndex(uuid, shards)`. Object and edge records use the same UUID-hash routing contract as the native batch API; source numeric IDs remain provenance only. No full-dataset preprocessing or per-object routing directory is required.

```json
{
  "source": "/datasets/fibers.afv",
  "output": "/scratch/fibers.vcobj",
  "volume_id": "catalog-volume-id",
  "batch_size": 256,
  "batch_bytes": 67108864,
  "fiber_limit": 1000,
  "report": "/scratch/import-report.json"
}
```

Build the `vc_object_import_afv` target in a normal vc_object_store CMake build (`VC_OBJECT_STORE_BUILD_TOOLS=ON` or `VC_OBJECT_STORE_BUILD_TESTS=ON`). Start with a finite pilot; set `fiber_limit` to zero for the entire source. `volume_id` is the actual catalog volume identifier, not a newly generated UUID. Alternatively specify `unbound:true`. `scale_factor` defaults to 1 and records the coordinate binding without transforming samples.

Every original float64 XYZ byte is retained in `line_points`. Both the native importer and Python `scripts/import_afv.py` declare empty control arrays, with no invented control points or IDs. This changes the older Python AFV import's synthetic endpoint-control behavior; actual control points in other input formats are unaffected. Fiber names, families, point counts, lengths and bounds stay in core fields; original numeric IDs and free-form annotations use `ext_fiber_graph_solve_sources`. Provisioning is explicitly constructed from source identity, optional checksum/counts and fixed conventions; source metadata trees, selection-ID lists, reports and filesystem paths are not copied into it. There is no synthetic collection object or repeated per-fiber provisioning JSON. See the [fiber graph solve extension](extensions.md#fiber-graph-solve-extension-format-1).

Optionally add `"constraints":"/datasets/constraints.afc.sqlite"` to import the associated integer-ID AFV constraint database, with one edge per original constraint. Its declared AFV UUID must match. The stable source constraint UUID is its native edge UUID: independent observations of the same pair remain separate without inventing geometry dependencies or per-observation edge kinds. For a fiber-limited pilot, only edges between imported fibers are eligible; `constraint_limit` selects a prefix of eligible edges ordered by source ID, and zero means all eligible edges. Neither input is changed. Reports separately count/timestamp edges and mark whether constraints were imported. A geometry-only run reports `constraints_imported:false` and does not claim to be a complete winding-solver dataset. Newer AFC files with UUID object endpoints do not need AFV ID translation and are intentionally rejected by this adapter. Unknown constraint columns are rejected rather than silently dropped.

The decoder validates format/version, completeness, native-coordinate declarations, block ordering, identical shared block endpoints, catalog point counts, finite coordinates and bounds. Full scans also validate collection totals. Parallel imports check aggregate fiber, point and constraint counts from their existing worker counters before publishing the destination; a mismatch removes private staging and permits retrying the same output path. Prefix/filtered imports compare only applicable totals, not full-source counts for omitted rows. Import reports separate source decoding, store ingestion, sealing and final persistence. With `verify_readback:true`, every imported fiber is additionally read back and compared exactly; this diagnostic is timed separately and is not part of normal import. Extrapolations are labeled estimates and exclude readback time. A prefix pilot can have a different length distribution than the full volume, so report exact full-volume measurements when available.

`source_open_seconds` measures initial source opening; `end_to_end_seconds` includes that setup, the import pipeline, final export and optional validation. Subtract `validation_seconds` for normal import latency. The older `total_seconds` starts inside the pipeline after opening the source. `source_read_seconds` and `constraint_source_read_seconds` are reader-worker preparation sums, excluding queue push time; they overlap and must not be added to ingestion wall time. The prepared-input benchmark offers an explicit [matched AFV-record mode](../benchmarks/README.md) for comparing this adapter against the same native import API with records already in RAM.

## Shards and packed containers

Set `shards` to the writer count (1–256, default 32). Each independent SQLite writer receives UUID-routed batches, owns disjoint numeric ID reservations, performs one bulk transaction and seals with the same lineage UUID and commit sequence. Object UUIDs remain identical to the unsharded import. Numeric row IDs are internal and can differ with reader scheduling; they are not source identities. Every import receives a fresh logical store UUID shared by its shards. Without packing, multiple shards produce a directory containing `collection.vcobj` and its shard files. Set `shards:1` explicitly for a single ordinary SQLite file.

`readers` controls parallel source readers (default min(shards, 32)). The common `ParallelImportStream` dynamically claims coarse disjoint source chunks, rather than assigning one range per reader. AFV tasks target `source_chunk_points` (65,536) and `source_chunk_fibers` (1,024); a single long fiber remains intact. AFC numeric ID tasks target `source_chunk_edges` (2,048); gaps/filtering may change task sizes, which work stealing balances. Cursors are reused per reader. `per_reader` reports task counts, fibers, points, constraints, work time and queue waits. `batch_size` bounds rows per destination batch; `batch_bytes` (default 8 MiB) bounds each reader’s aggregate pending payload before flushing. `queue_bytes` (default 256 MiB) is split across destination queues for each of the object and edge streams; both can briefly coexist while the last objects drain. A single oversize batch per destination is allowed to ensure progress; SQLite caches, active consumer batches and source-reader buffers are additional memory. Readers finishing geometry can prepare edges while other readers finish their last geometry chunks; each writer still appends its objects before its edges. Pending memory pressure flushes the largest destination buffer instead of every small batch. `source_cache_bytes` (default 128 MiB) limits each source cursor's SQLite cache; `sqlite_cache_bytes` limits each writer cache. These are ceilings, not eager allocations, and are separate from packed VFS memory and SQLite bulk page preallocation. Waiting producers poll cancellation so failures cannot strand queue workers.

Add `packed:true` to create those independent databases directly through the packed VFS and publish one compact container at `output`. `resident_bytes` controls the packed writer cache (default 256 MiB); SQLite worker caches and active fibers are additional memory. Packed bulk writes are disposable until finalization, which durably publishes the container. A single uncompressed shard publishes an ordinary SQLite file; multiple uncompressed shards publish a directory. Combined geometry/AFC import supports all shard counts; separate relation-only overlays remain optional. Finishing the batch writes routing metadata from worker-owned descriptors, closes the writers and completes persistence/atomic exposure. It does not reopen the shards or the collection. Optional `verify_readback:true` reads through the composed collection and checks every imported fiber's bytes/core fields/source-extension row and every relation's endpoints/anchors/measurement-extension row. It is not part of normal ingestion. Reports separate pipeline wall time (including queue backpressure), native worker times, ingestion wall time, persistence and optional validation; overlapping worker timings must not be summed into wall time.

## Parallel relation-only overlays

After importing geometry, supply `geometry_collection` (the published collection manifest or packed container), `constraints`, and `shards` to import independent relation shards. `source` still identifies the original AFV namespace. `output` is a new directory, or a new single container with `packed:true`. Each worker holds a store_reference to the sealed geometry collection, stores its own native edges with original endpoint UUIDs and colocated measurement-extension rows, and seals independently; the final manifest composes those stores. Geometry is not copied. `constraint_limit` selects an explicit prefix for a pilot; zero imports the full AFC source. Readers scan contiguous constraint ID intervals, then dispatch each edge by its derived UUID; these read intervals do not determine destination placement. If `verify_readback:true` is requested, diagnostic readback resolves original endpoint UUIDs, compares anchors and typed measurements, and checks representative fiber geometry from the referenced store. Normal imports do not perform these reads.

`initial_batch:true` (default) uses `ObjectCollection::importInitialEdges`. The destination must be history-off and have no edges yet. The producer fills batches (`batch_size`, default 1024), with endpoint UUIDs (plus optional routing hints) and ordinary `EdgeRecord` values; it may read source data but must not mutate or commit the destination. A savepoint covers the complete stream, including allocated IDs and index changes. Exceptions roll back the stream, allowing a corrected retry in the outer transaction. Publication timestamps and ID reservations are shared within a batch. Trusted batch input skips endpoint existence/lifecycle/geometry lookups and cross-table identity scans; record-format checks and SQLite uniqueness/applicable foreign keys remain active. The producer is responsible for reference consistency. No endpoint directory or cache is built. Known nonunique lookup indexes are rebuilt at the end (`defer_indexes:true`); extension and uniqueness indexes are never removed. There is no alternate per-edge editing path in this batch command.

For ingestion without foreground payload disk writes, combine `packed:true`, `memory_first:true` and `background_flush:false`, with a sufficient `resident_bytes` budget. This is disposable bulk construction: it does not promise durability before successful finalization. Exceeding the resident budget fails the import rather than silently evicting to disk. SQLite caches and source batches consume additional memory. Finalization writes the compact container directly from retained RAM and durably publishes it; `persistence_seconds` measures this separately. `background_flush:true` permits background writeback while retaining strict memory-first residency. The ordinary bounded-cache VFS mode remains available with `memory_first:false` and can block on eviction I/O. None of these options changes the native records or permits publication of a partial import.

For an explicit allocator-contention comparison, `sqlite_memory_statistics:false` disables SQLite's global memory accounting before any SQLite initialization in this executable. It does not change production `ObjectStore` defaults, transaction semantics, or stored values. Keep the setting in the recorded local benchmark config when comparing runs; process peak RSS remains reported independently of SQLite accounting.

`sqlite_pagecache_bulk_bytes` optionally asks SQLite to allocate an initial page-cache block per connection rather than allocate each page separately after its small default block is exhausted. Zero preserves SQLite's default. This uses `SQLITE_CONFIG_PAGECACHE` with a null buffer and a negative KiB count, not a shared global memory pool. It can reduce the global page allocator's mutex traffic, but increases memory reservations for all connections in this executable, including source and referenced-store readers. It is an explicit standalone startup setting, not a production library default. Record its value and peak RSS when benchmarking; it does not change the page-cache size limit selected by `sqlite_cache_bytes` or the packed VFS budget.

`sqlite_cache_bytes` configures the SQLite page cache per connection, including readonly referenced-store connections when explicitly set. The batch command defaults its writers to 512 MiB; ordinary library and readonly-connection defaults remain 8,192,000 bytes (`cache_size=-8000`). Large randomly accessed relationship imports may need a larger budget, but the possible total multiplies by the worker count, referenced stores and connection pools. This setting is independent of the packed VFS's `resident_bytes` and native geometry caches; it is available to C++ callers as `OpenOptions::sqliteCacheBytes`. The report records the selected budget and measured process RSS.

For relation-import profiling, `profile:true` adds per-worker exclusive native phase timings to the final report; `profile_source:true` separately breaks down AFC cursor stepping, UUID construction, JSON parsing/serialization and remaining decoding. Periodic progress records show aggregate fiber/constraint counts and elapsed time; `source_pipeline_seconds` is the maximum individual reader elapsed time including queue backpressure, not the sum of workers or exact coordinator wall time. It overlaps insertion. Phase timings include waits, are opt-in, and must not be interpreted as CPU samples. Progress counts describe work attempted before transaction publication, not a validated completed import. Use short, externally time-limited trials for slow full-ID-range workloads and report extrapolated ingestion time separately from commit, readback and publication. Prefix-only pilots may miss the full graph's larger endpoint working set.

Source SQLite connections are single-reader cursors and use `SQLITE_OPEN_NOMUTEX`; each parallel reader owns its own connection and snapshot. No connection is used concurrently. `source_mmap_bytes` optionally requests readonly SQLite page mapping (default zero/off); `per_reader` records the actual build/platform-capped mapping sizes. This does not apply to destination VFS writes. Larger caches or source mapping need measurement, not assumption: a warm-source trial found no benefit from larger caches and worse throughput with mapping enabled. They must not silently replace the default based only on theoretical memory bandwidth.

For standalone SQLite contention diagnostics, additionally set `profile_sqlite_mutex:true`. Before initializing SQLite, the executable installs a forwarding overlay around its original mutex methods; no locks are removed. Each worker reports its own entry counts and one-in-1024 sampled entry latency for each static SQLite mutex category, plus an aggregate for dynamic/unrecognized mutexes. These are entry latencies, including uncontended overhead, not lock-hold durations; estimated totals extrapolate sampled observations. The optional profiler adds overhead and is not a production library setting or a substitute for an uninstrumented throughput comparison.

On Linux/macOS builds with `execinfo` and `dladdr`, `profile_sqlite_stacks:true` additionally samples a PMEM caller stack every 65,536 entries (`profile_stack_interval` may lower this for short diagnostics). Reader and writer snapshots are separate. Zero estimated wait without any samples means unmeasured, not zero contention. At most 32 distinct eight-frame stacks are retained per thread; excess distinct samples are counted. Capture happens before acquiring the lock, symbol resolution only when reporting progress. This requires mutex profiling and is disabled by default; stripped libraries may expose addresses rather than all function names.

Core edges retain endpoint identities, kinds and anchor positions. AFC arc offsets, normals, winding distances, classification scores, evidence weights and known diagnostics are typed columns in `ext_fiber_graph_solve_constraints`, not `meta.afc` JSON. The two source distance fields remain distinct as `las_winding` and `parallel_las_winding`. The source decoder returns an `AfcConstraint` carrying the core edge and its extension row; neither normal vectors nor measurement scalars are disguised as core tangent fields.

Extension values keep source A/B order. `source_reversed` explicitly relates that order to the core edge's canonical endpoint order; no guessed winding-sign flip occurs. Equal duplicate values in source diagnostics are omitted, while unknown fields or differing duplicate values remain in nullable `extra` JSON. Compact source identities, scalar counts and units live in extension provisioning once per table. AFC has no file UUID: its recorded fiber-source UUID is not presented as a constraint-file identity. One source constraint remains one edge plus one measurement row, with no pair bundling or expansion into competing integer winding links. Optional readback compares typed extension values as well as core endpoints/anchors and source annotations. The importer creates only source/constraint tables; optional classification, normal-sign, winding, layout and fulfillment result tables are for later workflow writers, not extra import work.
