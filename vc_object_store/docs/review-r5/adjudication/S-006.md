# S-006 adjudication

Decision: **confirmed defect, P2**. Independent GPT-6 Astra source review at `bea32d5d807731d8c3b2db17c815cde748523226`; no catch-and-commit execution.

The public overload in `include/vc_object_store/object_links/ObjectLinks.hpp:117` accepts a caller-owned `WriteTxn`. Its definition in `src/linking/LinkCandidates.cpp:184` calls `commitCandidatesImpl` directly without an operation-wide savepoint. That implementation removes stale pending edges at lines 91–107, then parses each incoming candidate's metadata at line 118. Candidate identity/key preparation does not parse this metadata, so a candidate with otherwise valid endpoints/anchors but invalid JSON can pass the early stages, follow a successful stale deletion, and then throw.

If the caller catches the exception and commits its still-live transaction, the previously successful deletion persists. Individual edge-operation savepoints do not encompass the whole candidate batch. This violates the explicit public-batch rollback contract in AGENTS.md and the coherent-store contract.

Qualification: the overload owning its own transaction rolls back on exception unwinding and is not the counterexample. The failure is rejected input inside a supported public composition workflow, not malformed database contents. Put the shared savepoint at the common batch boundary used by caller-owned and stored-candidate paths; prevalidating only metadata or moving deletion later would not cover later operation failures. No duplicate among current candidates.
