Decision: **confirmed defect, P2**. Independent GPT-6 Astra source review at `bea32d5d807731d8c3b2db17c815cde748523226`; no resource mutation execution.

`projectResourceUuid` in `src/Project.cpp:148` hashes `"vc_project_resource/" + kind + "/" + location + (owner.empty() ? "" : "/owner/" + owner)`. For the same supported resource kind, shared location `/datasets/owner/alice` and owner `alice`'s private location `/datasets` produce exactly the same name bytes. This is a tuple-encoding collision, not a probabilistic UUID hash collision. `projectResourceRecord` rejects empty locations but does not exclude either valid path or encode field boundaries.

The native `addProjectResource` looks up that UUID and uses it for a checked update; the Python binding likewise calls `projectResourceRecord` and upserts. Adding the private resource after the shared one changes metadata owner and location on the same record, so the two intended resources cannot coexist. `projectResources` filters nonmatching owners, permitting the formerly shared record to disappear for other viewers.

Qualification: exact behavior can vary with additional write constraints, but UUID equality and inability to represent both identities are unconditional for the given tuple pair. This is not a security authorization claim. Fix the shared key encoding with an explicit legacy compatibility/migration policy and collision detection, not consumer aliases.
