# P-002 adjudication

Decision: **confirmed defect, P2**. Independent GPT-6 Astra source review at `bea32d5d807731d8c3b2db17c815cde748523226`; no concurrent export execution.

`tracers/fibers/tracing/volume_store.py:85` derives a deterministic `.writing.vcobj` sibling, unlinks it, asks `write_fibers` to produce that path, then replaces the destination. The shared writer already builds in its own `TemporaryDirectory` and publishes with `os.link(staged, destination)` after the store is closed and checkpointed (`tracers/shared/annotations/fiber_store.py:150`). Its no-clobber publication does not protect the extra intermediate pathname after it returns.

If A finishes writing the intermediate file and pauses, B can unlink that completed A file. A's later replace either fails or moves a newly published B file; its returned counts can then describe A rather than the published content. The tracing module explicitly supports live manual export, and run completion also exports, so overlapping same-target operations are a real supported workflow combination.

Qualification: the count mismatch requires differing snapshots, while the spurious failure does not. Sequential replacement is intentional and must remain supported. Add an explicit replacement policy to shared publication, keeping per-invocation staging ownership through the final rename. This is a runtime concurrency defect with an architectural cause, not merely duplicate helper code.
