Decision: **confirmed defect, P2**. Independent GPT-6 Astra source review at `bea32d5d807731d8c3b2db17c815cde748523226`; no runtime reproduction.

The actual `DependencyGeometry` holds array descriptors and a byte-range reader. `pointValue` in `src/geometry/Dependencies.hpp:146` reads surface XYZ and applies the canonical coordinate predicate, but never reads the `valid` channel. `validateDependencies` uses that result when an edge has explicit point dependencies. Further, `dependenciesChanged` skips a point when its coordinate-array fingerprint is identical, independently of any change to `valid`. `updateSurfaceChannels` in `src/geometry/Geometry.cpp:679` changes descriptors but leaves the prospective reader bound to old geometry; its comment explicitly assumes unchanged points suffice.

The supported validity contract in `docs/editing.md:76` requires both coordinates and nonzero validity. An explicit grid-point relationship can consequently be created on a masked hole, and masking an already anchored vertex can leave the relationship applicable. Neither requires malformed geometry or a missing coordinate array.

Qualification: whole-geometry anchors and anchors explicitly depending on the entire `valid` channel already take broader change checks; they are not the counterexample. Add selected/prospective per-vertex validity to the shared dependency abstraction and its fingerprint shortcut without making unrelated vertex masks invalidate every point anchor. This concerns graph validity, distinct from C-001 and N-001 coordinate conversion.
