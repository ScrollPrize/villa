Decision: **confirmed defect, P2**. Independent GPT-6 Astra source review at `bea32d5d807731d8c3b2db17c815cde748523226`; no GUI/runtime reproduction.

The exact signature of `CState::savePointCollections` is `void`, not bool. It throws if ordinary collection synchronization fails, then emits the void `pointCollectionsSaveRequested` signal (`CState.cpp:767`). That signal is connected directly to the bool-returning `SegmentationModule::saveCorrections` (`SegmentationModule.cpp:232`); its return is not consumed. The slot catches a checked write failure and returns false (`SegmentationModule_Session.cpp:420`). Accordingly `prepareStoreSwitch` in `CWindow.cpp:1126` sees no exception from this failure and cannot veto based on that result.

`CloseVolume` tears down editing and then invokes `closeAll`, which eventually clears point collections. The teardown itself also calls `saveCorrections()` unchecked in `endEditingSession` at `SegmentationModule_Session.cpp:136`. Thus an anchored correction conflict can be followed by clearing pending state. Successful unanchored synchronization does not rescue the anchored edits.

Qualification: unrelated pending surface autosave or another editor may separately veto some switches; choose a correction-only edit with no such blocker. This is not a claim that every close discards data or that healthy saves fail. Use a shared checked editor-close protocol and preserve data on refusal. The selection-change and begin-editing guards protect different entry points and do not make this duplicate.
