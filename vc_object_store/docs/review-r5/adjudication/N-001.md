# N-001 adjudication

Decision: **confirmed defect, P2**. Independent GPT-6 Astra source review at `bea32d5d807731d8c3b2db17c815cde748523226`; no native GUI/runtime reproduction.

The selected-revision overload of `load_quad_from_store` in `volume-cartographer/core/src/QuadSurfaceStore.cpp:95` calls shared `readSurfaceGrid`, copies its points, and then applies `vcr::tifxyz::vertexValid` to every copied point. The actual helper in `vc_reader/include/vc_reader/tifxyz.hpp:43` requires every coordinate to be nonnegative; it is not the store's validity predicate or a full-sentinel check. Therefore source-valid `(1,2,3)` mapped by x translation -3 loses its finite target coordinates and becomes `kInvalid`. The grid's independently supplied validity mask is copied later and cannot restore those coordinates.

`StoreSurfaces::load` calls this overload with a transformed view when a volume is selected. The store contract explicitly permits valid transformed negative coordinates and keeps validity separate. The defect therefore occurs on ordinary native loading, with a matching selected reference and transform, without requiring any save.

Qualification: a published bad round trip is not independently demonstrated here; the direct proven failure is lost loaded coordinates/inconsistent mask. Preserve shared transformed coordinates and validity in the common native adapter, while handling any true resident-sentinel collision explicitly. Not a duplicate of C-001's inverse edit conversion, or of already-fixed Lasagna mask handling.
