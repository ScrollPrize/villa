# P-002: tracing export adds a shared predictable staging filename around the already-staged writer

Priority: P2 candidate (concurrent publication and wrong layer). Baseline `bea32d5d8`. Code trace only, not runtime reproduced; Astra adjudication pending.

Locations: `vesuvius/src/vesuvius/neural_tracing/tracers/fibers/tracing/volume_store.py:67–89`; shared writer `tracers/shared/annotations/fiber_store.py:150–199`; automatic completion caller `tracers/fibers/tracing/volume.py:803`. The tracing export is also a public CLI callable while a run is live; replacement on re-export is intentional and tested in `tracers/fibers/tests/test_fiber_store_sources.py:39–49`.

Actual: `write_fibers` already owns a unique sibling staging directory and atomically publishes a complete new database. To get replacement rather than no-clobber behavior, its caller stages a second time at a deterministic `<destination stem>.writing.vcobj`, unlinks whatever is there, then renames that pathname to the destination. If export A has published its completed database at that intermediate name but has not renamed it, export B can unlink it. A can fail despite its completed work, or rename B's completed file if B publishes before A resumes; then A's returned counts need not describe the published database. A live manual export overlapping the automatic completion export is a supported way to share the output path.

Expected: publication policy belongs to the shared writer; each invocation owns its temporary path until the final atomic publication. Preserve the deliberate re-export replacement behavior, not an unrelated blanket prohibition on replacement. If simultaneous replacements are allowed, last successful publication can win, but an operation must not move/delete another invocation's private staging file or report its counts as its own.

Shared fix direction: expose an explicit replacement policy on the already-staged writer or use a shared publication helper with no-clobber as the default and atomic replacement as an opt-in. Remove the extra caller-local unlink/rename staging protocol. Do not add a second fixed temporary path or require a new store schema.
