# N-002: correction-save failures cannot veto project close through the void save signal

Priority: P2 candidate. Baseline `bea32d5d8`. Evidence: source/caller trace, no GUI/runtime reproduction. Independent adjudication pending.

Locations: `volume-cartographer/apps/VC3D/CState.cpp:767–795`; `segmentation/SegmentationModule.cpp:232`; `segmentation/SegmentationModule_Session.cpp:420–440`; `CWindow.cpp:1126–1138,4778–4795`.

Trigger: edit anchored correction points, then make their checked save fail (for example an external commit invalidating the loaded correction membership baseline). Close the project/volume, or switch packages through the normal close path. `CState::savePointCollections` checks the ordinary unanchored collection sync, but asks the segmentation module to save anchored corrections using the void `pointCollectionsSaveRequested` signal. The connected `saveCorrections` catches the error and returns false; Qt discards that slot return, so `savePointCollections` reports success. `prepareStoreSwitch` also calls that method and therefore cannot observe the refusal unless unrelated surface autosave is pending. `CloseVolume` ultimately invokes `CState::closeAll`, which repeats the same unchecked signal, clears surfaces and calls `_pointCollection->clearAll()`.

Thus the correction failure is logged but does not prevent destructive teardown of pending UI data. R4's begin-editing preflight protects restarting the same editor, and the surface-panel guard protects selection changes; neither repairs the close/preflight protocol. Healthy saves are not the trigger. The issue is specifically failed persistence followed by teardown, not an ordinary clean close.

Shared direction: make pending-edit save/veto a shared checked close/switch operation that reports every registered editor's failure before clearing state. Avoid separate best-effort void notification paths for anchored and ordinary collections. Keep failed data and its original baseline, rather than relabeling it current or clearing it. A regression should force an anchored correction write conflict and verify close/package switch is refused and UI data remains, while a successful retry allows close. No production or test edits in this review.
