# S-007: server CLI narrows the requested port before checking its range

Priority: P3 candidate (input-boundary inconsistency). Baseline `bea32d5d8`. Source trace only; no server launched. Astra adjudication pending.

`vc_object_store/apps/vc_object_server.cpp:33–38` casts `std::stoul(value)` directly to `uint16_t`. `ServerOptions::port` is already `uint16_t`, so downstream server construction cannot recover the original value. For example, `--port 65536` parses successfully on supported Ubuntu/macOS, narrows to zero, and requests an ephemeral listener rather than rejecting an invalid port. Explicit zero can remain the legitimate ephemeral-port request; wrapping into it is not the same request.

Expected: the CLI adapter should reject out-of-range or only partially parsed numeric strings before converting them into typed server options. Reuse a checked argument parser or a small shared boundary helper if one exists; do not add validation after narrowing or a second interpretation of port values inside the transport server. The MiB shift options on the following lines merit the same checked-boundary pattern, but the proposed trigger here is the port narrowing, not an asserted payload-limit exploit.
