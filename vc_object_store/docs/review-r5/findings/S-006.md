# S-006 — Caller-owned link candidate batch can leave partial edits

- Priority: P2 candidate, supported public batch mutation.
- Entry point: `vc_object_store/include/vc_object_store/object_links/ObjectLinks.hpp:117`, `commitCandidates(ObjectStore&, WriteTxn&, ...)`.
- Reachable state: make an initial pending edge from a detector. Call the public overload inside a caller-owned transaction with stale replacement enabled, that edge in scope, and a new candidate with invalid JSON or a metadata array. Catch the validation exception and commit the surrounding transaction.
- Evidence: `vc_object_store/src/linking/LinkCandidates.cpp:91–107` removes stale pending edges before the new candidate's metadata is parsed/validated at lines 118–120. The public caller-owned wrapper (lines 184–190) invokes the implementation without a savepoint. The independently owned transaction wrapper is already safe on unwind; individual edge operations cannot roll back earlier successful operations in the same batch. `AGENTS.md:247` explicitly requires public batch writes to roll back even when a caller catches an error and commits.
- Shared fix direction: use the same shared `detail::Savepoint` at the common batch boundary used by both direct and stored-candidate entry points, so validation or cancellation after the first edit restores the entire candidate operation. Do not move deletion later as the sole fix; a subsequent insert/update may also fail.
- Verification status: static trace; add a catch-and-commit regression with an existing stale edge that must survive the failed batch.
