# C-003 — Object copy can silently omit extensions in referenced stores

Candidate priority: P2. Source-only review.

- Protection: `vc_object_store/src/ObjectCopy.cpp:9–30` rejects copies when the reader reports extensions or the selected object's metadata contains `vcobj_extensions`.
- Status: `vc_object_store/src/Versions.cpp:461–472` reports only `hasExtensionTables(db)` for the root connection.
- Public caller: `vc_object_store/src/ObjectStoreSession.cpp:554–572` uses the helper for copy/import across attached stores.
- Contract: `vc_object_store/docs/extensions.md:145–158` permits unversioned colocated import rows and explains that selected-object copy rejects unsupported extensions instead of silently doing a core-only copy.

Trigger: Import a fiber with a colocated immutable result row using an initial extension table with `versioned=false`. Seal that base and reference it from an overlay that has no registered extensions of its own. Copy the inherited fiber via the overlay attachment. The row is part of the base extension, not a manual snapshot pointer in the core object's metadata, so neither guard fires. Only the core record, geometry and geometry annotations are copied. The same fiber copied directly from the base is refused.

Expected: The protection should work independently of physical placement. It should not advertise an extension-aware copy that has not been implemented. If immutable result tables are intentionally excluded rather than considered copyable, that needs to be an explicit policy, consistent for local and referenced sources.

Shared fix direction: Provide an extension-preservation check through the same shared logical reader used for selection, with an explicit scope (winning source/selected entity or conservative whole source closure, according to the copy policy). Avoid repurposing a physical-root status flag as a logical preservation check. Test the same fiber with a populated unversioned result table, directly and through a referenced overlay, and ensure the hosted reader has the same safety policy.
