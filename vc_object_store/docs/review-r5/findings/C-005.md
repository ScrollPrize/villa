# C-005 — Ordinary checked metadata edits accidentally require retained relationship history

Candidate priority: P2. Source-only review.

- `vc_object_store/src/StoreReader.cpp:188–222` appends `KeepRecordedRelationshipOp` to every incident edge that did not already receive an explicit decision, regardless of what the edit changes.
- `vc_object_store/src/ObjectStoreSession.cpp:610–650` uses that helper for `editRecords` and `tagObjects`; VC3D invokes these for ordinary surface edits in `volume-cartographer/apps/VC3D/SurfacePanelController.cpp:592,1810`.
- `vc_object_store/src/History.cpp:1090–1124` refuses to keep a history-off local relationship after any endpoint appears in `changedObjects`. This includes edits that do not invalidate an anchor. `History.cpp:439–467` already implements the actual dependency comparison for current-only transactions.

Trigger: Use an editable history-off store with a local active surface and a local relationship attached to it. Add a new tag or change the surface name via `ObjectStoreSession::tagObjects/editRecords`, leaving geometry, lifecycle and all edge metadata dependency keys unchanged. The object update registers a changed endpoint. The helper's gratuitous keep-recorded operation then throws `recorded relationship endpoints are not retained; revalidate or remove it`, rolling back the edit. A checked direct metadata request with the required endpoint expectations but no automatic keep operation can leave this same relationship alone. Enabling history allows the session edit.

Expected: An unrelated metadata edit should not need historical retention. The documented restriction on explicit `keep_recorded` applies when an edit changes an observation's dependencies, not when the observation is still applicable.

Shared fix direction: Keep endpoint guarding in the common request builder but avoid adding a keep decision for an unaffected relationship. Make the writer's shared dependency applicability/validation own this distinction so each consumer does not replicate anchor or history logic. Do not silently revalidate affected edges or enable history. Regress name/tag changes alongside truly affected geometry edits under both retention policies.
