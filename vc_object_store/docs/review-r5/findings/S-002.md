# S-002: registered remote ingestion wrongly requires source-record UUID parsing

Priority: P2 candidate. Frozen baseline `bea32d5d8`. Evidence: source-traced supported workflow; no runtime reproduction. Independent adjudication pending.

Locations: `vc_object_store/src/geometry/GeometryIngest.cpp:162–174`, `src/formats/SurfaceInput.cpp:83–94`, `src/formats/GeometryInput.cpp:14–31`; contrast `src/catalog/CatalogStore.cpp:233–239`. Contract: `docs/ingestion.md:139–160` states that the placeholder, not the remote `meta.json`, supplies object identity.

Trigger: register a surface with a valid store UUID and `storage_kind="url"`, then ingest its valid remote tifxyz geometry whose `meta.json` has a legacy timestamp-like segment ID or no `uuid`. This is the existing public `ingest_registered_geometry` path (see `tests/python/test_workflows.py:167–192`).

Actual: after downloading the files, the adapter calls `formats::surface(staging)` without a UUID namespace. That full source-registration adapter invokes `sourceObject`, which unconditionally canonicalizes `meta.json.uuid`. It fails before the caller can replace the UUID with the already registered object's UUID. The catalog fetch path downloads the same geometry but correctly calls geometry-only `surfaceGeometry`, which does not impose that source-record requirement. The existing remote workflow test uses a UUID-bearing fixture and does not exercise the distinction.

Expected: decoding bytes into an existing registered object must not construct or validate a second source identity. The registered UUID remains authoritative; real geometry/format checks should remain.

Shared fix direction: share the remote staging and geometry-only decode boundary between registered ingestion and catalog fetch, with RAII cleanup; let each caller apply its existing record/provenance and coordinate policy. Do not invent a namespace or rewrite `meta.json` to make an unnecessary source-record parser succeed. Extend the existing loopback remote fixture with absent/non-UUID source identity while preserving local ingest's explicit source UUID requirements.
