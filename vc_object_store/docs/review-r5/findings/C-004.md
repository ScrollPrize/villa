# C-004 — A draft checkpoint can name a durable request that has not been staged

Candidate priority: P2. Source-only review; the trigger is an interleaving, not a malformed checkpoint file.

- `vc_object_store/src/ObjectStoreSession.cpp:1018–1052`: `submitDurably` publishes the pending record and draft association under `mutex_`, releases that mutex, and only then takes `durable_->writing` to persist the request and payloads.
- `vc_object_store/src/ObjectStoreSession.cpp:959–982`: `checkpointDrafts` holds `durable_->writing`, but captures every in-memory pending record, including one waiting to acquire that lock for staging.
- `vc_object_store/src/DraftCheckpoints.cpp:149–152,172–190`: the manifest makes those request names durable independently of their files; replay needs the exact request file and payloads.
- `volume-cartographer/apps/VC3D/SessionDrafts.cpp:105–124`: the app checkpoints periodically on a separate Qt worker. `volume-cartographer/apps/VC3D/segmentation/SurfaceStoreEdit.cpp:174–180` uses durable save. The sequencing can also occur with two direct C++ calls, consistent with `vc_object_store/docs/hosted.md:220–240` scheduling checkpoints separately from saves.

Trigger: A save publishes its in-memory pending record, then is preempted before acquiring the writing lock. The periodic checkpoint gets the lock first and atomically replaces the previous manifest with one naming that pending request. A crash after the manifest replacement and before staging leaves a recovered submission with no corresponding saved request or receipt. `resolvePending` cannot replay it; the previous checkpoint that did not name this request is no longer active.

Expected: Every pending request named by a completed checkpoint should be replayable after a crash. A crash before request staging may lose the uncommitted save, but should not publish it as a pending recovery record.

Shared fix direction: Publish the in-memory pending record and its durable manifest only after staging succeeds, using one shared checkpoint transaction/lock protocol that cannot expose unstaged draft associations. Test a forced interleaving between save staging and periodic checkpoint publication; recover before the save sends anything.
