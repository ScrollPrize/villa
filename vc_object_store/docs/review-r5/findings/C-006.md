# C-006 — Catalog refresh replaces metadata it does not own

Candidate priority: P2. Source-only review.

- `vc_object_store/src/catalog/CatalogStore.cpp:35–58` constructs a placeholder with only catalog-owned coordinates, provenance and catalog fields.
- `vc_object_store/src/catalog/CatalogStore.cpp:94–110,151–193` treats changes to other fields as a catalog refresh difference, preserves tags and selected surface attributes, then submits the placeholder's entire metadata as an `UpdateObjectOp`.
- `vc_object_store/src/internal/RecordSql.cpp:448–460` replaces the full metadata; `checkExtensionMetadata` blocks removal of a managed extension snapshot but does not preserve general metadata or the artifact manifest. `vc_object_store/include/vc_object_store/objects/Artifacts.hpp:6–26` locates the selected artifact manifest in that metadata.

Trigger: Fetch a catalog surface and use the normal artifact publisher to attach a result without editing its geometry. Refresh that unchanged catalog. The geometry still matches `catalog_geometry_revision`, so the surface is not treated as locally edited. `sameCatalogRecord` sees the artifact manifest absent in the placeholder, schedules an update and drops the manifest from the current surface. Artifact bytes may still exist, but the current surface no longer exposes the result. The analogous metadata edit with a managed manual extension makes refresh throw instead.

Expected: A catalog refresh should compare and update the fields it owns, preserving independent metadata, artifact references and extension snapshot references. Updating an upstream URL can trigger a re-fetch, but an unchanged catalog should not remove published results or change the surface's version.

Shared fix direction: Apply catalog-owned field patches to the selected record through the normal checked edit path, preserving fields the adapter does not own. Share the ownership definition between comparison and update so they cannot disagree about no-ops. Regress no-op refresh and real catalog-field changes with an attached artifact or managed extension. This is distinct from C-003: it mutates an existing object rather than copying one across stores.
