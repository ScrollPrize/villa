# C-001: transformed surface edits apply the canonical validity predicate in the target frame

Baseline: `bea32d5d8`. Priority: P2 candidate. Evidence: source-traced public API path; no runtime reproduction. Independent Astra adjudication pending.

Location: `vc_object_store/src/geometry/GeometryViews.cpp`, `inverseSurfacePoint` (the validity test before `inverse.apply`), consumed by `surfaceEdits` and `canonicalSurface`. The canonical predicate is defined in `include/vc_object_store/geometry/Geometry.hpp:80–85`. Reachable through the documented `surface_edits` / `edit_transformed_surface` APIs and the VC3D surface save's `quad_rect_edit`/`canonicalSurface` calls.

Trigger: a valid canonical vertex `(3,2,3)` is viewed under an x translation of −3, displaying `(0,2,3)` as valid. Edit its target position to `(-1,2,3)`. The inverse-mapped canonical point would be `(2,2,3)`, which is valid. Nevertheless `inverseSurfacePoint` calls `validSurfacePoint(desired)` before applying that inverse; the target's x component of −1 causes it to return `(-1,-1,-1)`. A valid geometric edit therefore deletes the vertex. Similarly a target z≤0 can correspond to a valid canonical z after a translation but is rejected in the wrong frame.

The shared transformed reader already preserves validity from the canonical source (`TransformedGeometryView::readTile`), and `docs/transforms.md` explicitly distinguishes canonical validity from transformed coordinates. R4 fixed consumers dropping that read mask, but the shared write conversion still performs a second target-coordinate interpretation. This is distinct from the rejected R4 mismatched-view API-hardening candidate: the view, selected object and mapping here all match, and the desired point is a legitimate inverse-mappable edit.

Shared fix direction: make the transformed edit conversion distinguish an explicit missing/deletion intent from target coordinates, then validate the inverse-mapped canonical point. Keep no-op bit preservation and invalid-source restoration semantics. Use one conversion for rectangle edits and full replacement rather than patching GUI consumers. Regression should exercise a valid edited target component equal to −1, a target z crossing zero under translation, explicit deletion, and unchanged masked vertices.
