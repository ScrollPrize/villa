# C-002: measured/volume selection compares a cursor UUID without canonicalizing it

Baseline `bea32d5d8`. Priority: P2 candidate. Source-traced, not runtime-reproduced; independent adjudication pending.

Locations: `vc_object_store/src/Queries.cpp:188–191` (`measuredSelection`), contrasting with the shared SQL selection cursor at `Queries.cpp:94–103`. `src/Wire.cpp:279` reads `after_uuid` as supplied and does not canonicalize it.

Trigger: a fiber with canonical UUID beginning with alphabetic hex (for example `aaaaaaaa-...`) is the cursor row of a length-ordered query. Pass the equivalent uppercase UUID as `afterUuid`, together with that row's measured `afterLength`. The measurement path obtains lowercase `row.uuid` through `formatUuid` but compares it directly to the uppercase caller string; lowercase `a` sorts after uppercase `A`, so the cursor row is returned again instead of being excluded. UUID-ordered volume selections take the same raw-string comparison and can repeat or skip valid rows. The ordinary non-volume UUID SQL path parses the same alias into binary and behaves correctly.

This is a supported UUID spelling accepted elsewhere by the common parser, not malformed UUID input. The wire carries it unchanged into selection. Automatically generated cursors are lowercase, but public C++/Python/hosted cursor APIs also accept caller-supplied UUIDs. Identical logical requests therefore produce different pages depending on spelling and whether measurement/volume processing is active.

Shared fix direction: normalize cursor identity once in the common selection validation/preparation path before any SQL or in-memory comparison. Do not add a separate uppercase workaround in clients. Regressions should compare canonical/uppercase/other accepted parser aliases for native length order, UUID volume order, equal-length ties and the unbound-tail transition.
