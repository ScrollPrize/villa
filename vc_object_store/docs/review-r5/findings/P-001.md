# P-001: UV preparation drops the frozen source guard before reading geometry

Priority: P2 candidate. Baseline `bea32d5d8`. Code-traced concurrency trigger, not runtime reproduced; Astra adjudication pending.

Locations: `vesuvius/src/vesuvius/neural_tracing/fiber_trace_3d/fiber_uv_layout.py:121–143,191,240–248`; shared verification in `fiber_hv_stage.py:60–73`; guarded reader in `tracers/shared/annotations/fiber_store.py:107–124`.

Supported trigger: UV preparation records the original fiber digest and verifies extracted constraints/features against the source version recorded in the constraint database. After verification returns, another supported writable client edits a retained fiber, preserving its UUID and arc length (for example a translation). Preparation subsequently calls `read_polylines(..., volume=volume)` without the already available frozen `source_version`. That selects the new current geometry, while constraint endpoints, normal/sign solutions and the signature still describe the old source. Unchanged arc lengths satisfy the later arc-range checks. The resulting tensor cache is published with the original signature; no final source guard runs before publication.

Expected: use the selected source geometry for the recorded evidence, or reject source changes. The shared reader already supports `source_version` and validates it on both sides of the read. A signature checked earlier in the workflow is not a guard around a later geometry read. This is not asking every explicitly current read to be historical; this producer explicitly consumes frozen extracted evidence and persists a signed cache.

Shared fix direction: propagate the extraction's compact source snapshot through the common preparation/read boundary (and equivalent cache producers where applicable), rather than adding another UUID-only or freshly stamped provenance scheme. Do not re-run extraction silently or recertify old constraints against new geometry. The existing R3 H/V guard is correct for its own read but does not protect this later consumer after it has returned.

Qualification: this requires an edit during preparation, not merely launching preparation after an already-changed source; the latter is correctly rejected by `verify_feature_source`. A subsequent fresh preparation may detect a digest mismatch, but that does not make the already-published mixed-input cache or the current run correct. No destructive or full-volume probe was run.
