# P-005: Spiral's frozen object pins do not freeze overlay relationship membership

Priority: P2 candidate. Baseline `bea32d5d8`. Evidence: source trace and existing core regression as contract evidence; no new runtime reproduction. Independent adjudication pending.

Locations: `spiral-fitting/object_store_inputs.py:159–175,203–218,753–772,856–886`; `vc_object_store/tests/cpp/test_object_store_hosted_cache.cpp:140–169` demonstrates that membership can change under identical inherited endpoint references.

`InputPins` promises the relationships at the position's commit because "a relationship change versions both endpoints." That premise fails for sealed inherited endpoints: the overlay may create/remove a relationship while both complete endpoint references are unchanged, as the existing hosted graph-cache regression exercises. `read_snapshot` resolves exact object references but obtains relationships using a separate current-scope `relationships_at_versions(refs)` call. It neither passes a graph publication position nor pins the original relationship membership. `InputPins.from_manifest` extracts object references and the position, not the manifest's selected relationship references.

Supported trigger: pin a Spiral input selection containing two inherited endpoints, then add an applicable overlay relationship of a consumed family (for example approved patch overlap between inherited surfaces). Re-read the same old pins. The endpoint references still resolve and match, but the graph call now returns the newly added relationship. The snapshot's request still advertises the old commit; the consumed edge set or resulting digest can change. The same gap is possible during initial current capture after its last status check. This does not imply core's endpoint-applicability query is wrong: the consumer is treating current membership over pinned endpoints as a frozen graph snapshot.

Expected/shared direction: capture relationship membership with the same selected publication position, then retain complete selected relationship references and use a shared exact-graph resolver. If old pins have only endpoints and cannot prove retained membership at the claimed position, refuse the replay instead of substituting current overlay edges. Avoid Python-only reconstruction of physical graph/history. Regression: inherited endpoints with unchanged full refs; pin fit inputs, add/remove overlay link, then replay old pins in local and hosted modes and require the original graph or explicit refusal. No production/test changes in this review.
