# N-001: native QuadSurface adapter reinterprets validity after coordinate transformation

Priority: P2 candidate. Baseline `bea32d5d8`. Evidence: source/caller trace, no runtime reproduction. Independent adjudication pending.

Location: `volume-cartographer/core/src/QuadSurfaceStore.cpp:95–113`, especially the post-copy `vcr::tifxyz::vertexValid` loop at 102. Reachable through `StoreSurfaces::load` and `SurfaceCatalog::open` into native CLI and VC3D displayed/edited surfaces.

The shared `readSurfaceGrid` result supplies transformed points and a validity mask derived from the selected source geometry. The native adapter copies those points, then applies the raw tifxyz format predicate to each already transformed point and replaces every point with any negative component by `(-1,-1,-1)`. A source-valid `(1,2,3)` transformed by x translation −3 is `(-2,2,3)` with shared validity true, but native loading destroys its coordinates. A transformed x = −1 produces the same problem. This is not restricted to malformed source data: general volume registrations can contain translations/rotations; the store can validly map vertices into negative target coordinates.

The subsequent mask channel still carries the true shared validity, leaving coordinates and validity contradictory. Ordinary rendering/geometry conversion now sees a hole; native update can publish the sentinel instead of the selected source geometry. R4 fixed this family in Lasagna but left the native adapter's second predicate intact. `QuadSurface::gridVertices` itself accepts finite negative coordinates except the full missing sentinel, so arbitrary negative coordinates are not intrinsically unrepresentable by the resident geometry abstraction.

Expected/shared direction: consume the selected source-valid mask and preserve transformed finite coordinates. Resolve any actual resident missing-marker collision at the common adapter/geometry layer rather than silently rerunning a raw-file predicate in each consumer. Do not change canonical stored validity or invent another fallback.

This is distinct from a possible inverse-edit mapping issue in the core: this candidate destroys coordinates on read, before any edit request. Regression should compare shared-grid and native-surface output with valid negative target coordinates, explicit invalid source vertices and mask holes; then exercise a no-change native round trip. No code or tests changed in this inspection.
