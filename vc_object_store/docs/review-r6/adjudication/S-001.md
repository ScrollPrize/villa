# S-001 — accepted, P2, regression

The pure public UUID helper now always returns v2, but native/Python add selects an existing matching legacy UUID. Native update/remove only look up the supplied UUID. A legacy store's resource can therefore be added successfully yet not removed using the documented deterministic helper. Header still promises the same resource UUID in every store and describes `projectResourceRecord` as the record add writes. HEAD used the same legacy derivation in both paths.

Returned/listed UUID callers are unaffected; this is compatibility of the helper-to-operation path, not universal resource loss. Do not merge with C-002 or C-003. Source-confirmed, runtime untested; exact legacy tuple matching appropriately prevents blindly accepting a colliding legacy key but does not resolve this contract mismatch.
