# C-005 — accepted, P2, pre-existing explicit-mask sibling omission

Independent trace confirms `canonicalSurface` copies desired validity but never supplies that desired mask to `inverseSurfacePoint`. For old canonical (3,3,3), translation (-3,-3,-3), and desired displayed (-1,-1,-1) with mask 255, the unchanged shortcut does not fire and the missing-triple shortcut returns (-1,-1,-1), instead of inverse-mapped (2,2,2). `Surface::validate` permits that sentinel with a nonzero mask and `Surface::valid` still rejects it, so this becomes silent geometry loss rather than a validation exception.

Public native `canonicalSurface` and VC3D resized save with an explicit valid array reach the path. Coordinate-only edits cannot disambiguate the sentinel, and unchanged sentinel-displaying vertices are correctly preserved: neither is evidence against the explicit-mask trigger. HEAD rejected all invalid target coordinates at the same branch, so this is an old omission left by the R5 negative-coordinate fix, not a newly introduced regression. Distinct from C-001..004.
