# C-001 — accepted, P2, pre-existing

Independent source trace confirms the failure: `Project.cpp::addedAt` prefers the winning owner's earliest revision; `History.cpp::objectHistory` queries only that owner; `RecordOverrides.cpp::createRecordOverride` preserves creation time but does not copy history. The first local publication therefore replaces logical creation as the sort event after a metadata-only override. Public native metadata update and Python/native resource listing reach this path. Project selection shares it, but do not count that as a second defect.

HEAD already used first owner publication for resources and project selection. This is an incomplete sibling invariant, not an R5 regression or a bug in history routing. Runtime untested; local/reference history-on trace is sufficient for the example, packed/sharded variants remain untested.
