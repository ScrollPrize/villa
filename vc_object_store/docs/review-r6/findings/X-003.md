# X-003 — H/V direction preparation leaves geometry outside the verified source

Pre-existing sibling omission, present at `bea32d5d807731d8c3b2db17c815cde748523226`; source-confirmed, no runtime. Both H and V branches of `vesuvius/src/vesuvius/neural_tracing/fiber_trace_3d/fiber_direction.py::prepare` calculate a fiber digest (line 79), verify feature-source identity (89–91), then call `read_polylines` without the verified `source_version` (124). The shared reader only guards against a moving head when supplied a source version. If a fiber is edited after verification but before the read, preserving UUID/order and having enough arc length, tangent/prior output can be calculated from new geometry and stamped with the old signature (143–149). Inherited H data also checks the recorded digests but does not pin the later V geometry read.

The R5 work changes UV layout/reference preparation but does not touch this caller; it is a sibling reopening of the frozen-source contract, not a newly introduced regression. In contrast, `fiber_normal_sign_visualization` passes the verified source into the read. Test by publishing a revision between validation and geometry loading, running both direction families, and verifying that no stale cache/stamp is published; no placement change is needed to trigger it.

The downstream side of the same invariant remains open: `fiber_piece_split.py::split_graph` reads current curves to resample stored piece bounds; `fiber_soft_winding.py::prepare_samples` reads current curves to derive measured prior targets using the saved graph's `source_id` and arc bounds. A change after saved graph creation can mix old graph arc coordinates with new geometry even without a race inside the individual geometry read. Both still omit `source_version`.
