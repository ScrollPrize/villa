# C-005 — Full-surface inverse editing drops valid vertices at the transformed missing sentinel

Candidate P2, source-traced. `vc_object_store/src/geometry/GeometryViews.cpp:314–331` preserves validity separately when transforming: a canonical valid vertex can legitimately display as `(-1,-1,-1)`. `canonicalSurface` (lines 442–462) accepts the desired `Surface.validity` channel but forwards only the *old* validity to `inverseSurfacePoint` (lines 379–395). After checking the unchanged fast path, the helper treats the desired XYZ triple as missing regardless of explicit desired validity. `TypedGeometry.cpp:96–121` accepts the canonical missing triple even with a nonzero mask and determines the vertex to be invalid.

Trigger: under a translation of `(-3,-3,-3)`, start with a valid canonical vertex `(3,3,3)` displayed at `(0,0,0)`. Edit the full desired surface to place that vertex at `(-1,-1,-1)` with its explicit validity byte 255. Expected canonical output is `(2,2,2)` with validity 255; actual output is canonical missing XYZ with validity 255, which reads back as a hole. The same occurs for a newly appended vertex at that transformed coordinate, so no in-place edit is necessary. An unchanged already-valid vertex which happens to display at the sentinel is preserved by the early equality check; that control does not exercise the bug.

Sibling closure: native `canonicalSurface` has the explicit desired mask needed to disambiguate. The VC3D resized-grid save calls it with raw edited points and the `valid` array when a mask is present (`volume-cartographer/apps/VC3D/segmentation/SurfaceStoreEdit.cpp:125–140`), then submits the resulting canonical geometry. Its same-size sibling sends any changed mask in a preceding `SetSurfaceChannelsOp`; `quad_rect_edit` passes replacement validity to `surfaceEdits`, where the optional mask is baseline context for coordinate edits, not a standalone validity-edit API. The public native coordinate-only `writeSurface` and Python `edit_transformed_surface` take only XYZ, so an explicit missing triple remains ambiguous there; the documented/fixture deletion behavior must not be silently changed. Python's canonical `update_surface_channels` can express a mask-only edit without this inverse helper. For ordinary positions, a full-surface mask-only change with unchanged displayed coordinates preserves canonical XYZ and carries the desired mask. Do not conflate that case with moving a valid vertex to the sentinel.

Attribution: preexisting at HEAD, where the old target-frame validity predicate also rejected the full triple. R5 C-001 fixes other negative target coordinates but deliberately keeps the full sentinel branch; the explicit-mask sibling remains uncovered. Regression: compare a full-surface edit at the sentinel with mask 255, a masked vertex, unchanged sentinel-displaying geometry, a new masked/unmasked appended vertex, and the coordinate-only deletion control. No runtime tests executed.
