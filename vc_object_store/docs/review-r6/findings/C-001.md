# C-001 — First override makes an older project resource look newly added

Candidate P2, source-traced. `Project.cpp:15–18,115–152` ranks the first revision in the *winning owner's* history ahead of the preserved creation time. `History.cpp:863–873` queries that owner's revision table only; this is correct for history reads but is not a logical creation timestamp. `internal/RecordOverrides.cpp:80–86` preserves the original creation stamp when materializing an override; `History.cpp:686–696` timestamps the new local root revision with the current commit time.

Trigger: Add volume A to a history-on base, seal and reference it in a history-on writable overlay, add volume B in the overlay later, then edit metadata (not identity) on A using `updateProjectResourceMeta`. Both resources are still live and `projectResources` is documented to return order added. A initially sorts before B; after the edit, the winning A history begins at the override, so A sorts after B. Similarly, when two project records coexist, renaming the older inherited project can make subsequent `projectRecord` calls select the other project instead. The wrong record can also be renamed during copy because `copyProject` uses `setProjectName`.

Sibling closure: `projectRecord` and `projectResources` now share `sortByAdded`; C++ session readers and Python `project_record` / `project_resources` (bindings at `python/objects.cpp:1644–1658`) delegate. Local history-on updates without an owner change keep the original first publication; history-off wins use the fallback creation stamp and do not exhibit this exact override trigger. Referenced packed/sharded sources use the same logical reader; not runtime-tested. No finding claims a defect in `objectHistory` itself.

Attribution: resource reordering after a history-on override is already reachable at HEAD (old `projectResources` also used the winning owner's first publication). The R5 S-008 patch fixes comparing timestamp domains for untouched mixed-policy resources but does not fix logical creation versus local first publication. Regression test should capture order before and after the metadata-only edit, then mirror with two project records and a rename. Not run.
