# S-002 — Conversion reports are staged together but published independently

Priority: P2. Unresolved R5 S-005 publication boundary, with a changed in-place failure mode; source-confirmed.

`migration/ConvertStore.cpp:942–958` stages both JSON files, then publishes mapping and report with separate `StagedDatabase::publish` calls. `internal/Publication.hpp:11–25,36–43` rolls back only the destination of the individual publication that fails; the already published mapping is outside both destructors' cleanup. If the report path is occupied by a concurrent creator after preflight (or the second directory sync fails), the first mapping remains. In place, the error from the callback prevents the database replacement (993–997), but the stale mapping blocks the next normal retry (`apps/vc_object_convert.cpp:40–48`). Conversely, successful report publication occurs before replacement, so a later replacement failure leaves reports saying `validation: ok` and `in_place: true` for a replacement that never occurred.

In copy mode the CLI calls `convertStore` before `writeConversionReports`; even a deterministic missing report parent leaves a published database, and a retry cannot reuse its destination. This existed at HEAD (conversion preceded sequential truncating streams); the R5 overlay removes clobber races for JSON and pre-validates both parents before JSON staging, but not before copy publication. HEAD's in-place path replaced the database before either report write; this part is materially improved for predictable report preparation failures.

Sibling closure: raw native `convertStore` deliberately returns report content without writing reports; native `convertStoreInPlace` without the callback also has no report group. The new public report writer has the same sequential behavior as the CLI callback, and CLI-only alias/distinct checks are not inherited by direct callers. `changeHistoryMode` has no reports. The AFV importer has one optional report; geometry export protects the dependency closure and publishes a single selected export, neither establishes group behavior here.

Direction: preflight both output paths before either conversion mode; define failure and retry semantics for the multi-file publication and clean up only outputs proven to belong to this attempt. Test deterministic missing report parent for copy mode, a competing report path after staging, failure between report publications, and failure replacing the database after reports are ready. R5's invalid-directory test invokes only the report helper and does not exercise these orderings. No runtime probe here.
