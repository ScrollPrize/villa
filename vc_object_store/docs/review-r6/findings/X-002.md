# X-002 — Shared anchor decoder silently narrows Python point indices

Dirty R5-fix regression at the Python boundary; source-confirmed, no runtime. `python/StorageBindings.hpp:67` now serializes a Python dict to JSON and calls the native `anchorFromJson`. The shared `src/internal/Anchors.cpp:91` decodes `index` with `get<std::vector<int64_t>>()` without requiring integer JSON elements or checking bounds before conversion. nlohmann's arithmetic conversion narrows a float such as 10.9 to 10; the subsequent anchor check only checks the resulting integer is nonnegative. `fiber_branch_control_index([90, 10, 55], {"points": [{"array": "control_point_ids", "index": [10.9]}]})` can select ID 10 rather than reject malformed input. The same conversion can bind a wrong point in edge insertion/edit/repair when the narrowed ID exists.

HEAD `bea32d5d807731d8c3b2db17c815cde748523226` used nanobind's signed integer converter (accepts integers or `__index__`, checks overflow; floats and numeric strings are not integers). The native JSON decoder's loose conversion itself predates the dirty diff; command JSON, wire record decode, and persisted dependency decode already used it. Values above signed range also lack a pre-conversion check in the JSON path; a signed result that happens to be negative is rejected after conversion, not evidence of correct range validation. Numeric strings do not take the native arithmetic path, and are not a demonstrated new acceptance case. The Python binding now delegates field names, validation and serialization; omission of null fields preserves HEAD's `has` behavior and tuple restoration is output adaptation, not a duplicate semantic parser.

Test the same fractional and overflowing index via Python helper, add/update edge, checked edit and repair, plus native command JSON, retaining successful exact integer and NumPy integer inputs. Fix validation in the shared decoder, not by restoring duplicate Python anchor schema interpretation.
