# S-006: AFV import report can overwrite its source or the completed object store

Priority: P1. Baseline: `2b5d1e01fd26f27b3410d1b024c3f10a73533287`. Status: code-traced CLI path; no destructive reproduction run.

`vc_object_store/apps/vc_object_import_afv.cpp:348` opens the configured `report` with truncating `std::ofstream` after successful import. The command does not validate this path against `source`, `constraints`, `geometry_collection`, `output`, or their backing files. Setting `report` equal to `output` in a normal plain-file import successfully imports a database and then truncates it to JSON; setting it equal to the source AFV destroys the supposedly read-only input. Filesystem aliases/symlinks also reach this path. The source handle being SQLite-readonly does not protect it from the independent file stream.

Expected: the command must refuse report destinations overlapping any input/backing database, destination database/container, dependency file or protected sidecar before beginning work. It should also use shared atomic no-clobber publication for a new report, not an unchecked truncating stream. Reuse the common destination/closure protection rather than teaching this caller another partial vcobj resolver.

Regression: controlled fixtures where `report` equals source, constraints or output, plus hard-link/symlink aliases. Reject before any source modification or expensive import. Check that legitimate distinct report paths still work and that report-write failure does not misleadingly destroy a successfully published output.

Cross-model validation: pending.
