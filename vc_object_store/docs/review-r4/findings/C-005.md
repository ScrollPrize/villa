# C-005: Selected surface materialization checks geometry identity but not the supplied transform's metadata identity

Status: code-traced API-consistency candidate; independent-model validation pending. Priority P2. Baseline `2b5d1e01fd26f27b3410d1b024c3f10a73533287`.

Location: `vc_object_store/src/SurfaceGrid.cpp:38–61`; related selected-state construction at `src/geometry/GeometryViews.cpp:112–147`.

Trigger: retain a transformed view of surface revision A. Publish metadata-only revision B with a different coordinate declaration; A and B legitimately name the same immutable geometry UUID. Call public `readSurfaceGrid(reader, selectedB, &viewA)`.

The helper validates only `transformed->revision().uuid == canonical.revision().uuid`, then returns points transformed using A alongside B's record/reference. This silently certifies an old coordinate mapping with a newer selected metadata identity. Complete object identity, not geometry UUID alone, determines transformed coordinates. The API has an existing mismatch check, so it is explicitly trying to reject inconsistent inputs but misses this supported metadata-only case.

The transformed view currently does not consistently retain its explicitly supplied selected metadata reference: historical selected-state construction only assigns the reference if that state is still current, and `GeometryView::viewTransformedAt(selected)` may clear it. That makes a shared provenance comparison unavailable even when the selected metadata was explicitly passed. Edit eligibility may be restricted separately; exact read identity should not be discarded to enforce that restriction.

Shared fix direction: carry the selected `ObjectVersion` (and mapping baseline) in transformed views independently of whether writes are permitted, then validate supplied selected surface and transform through that shared identity. Avoid recomputing current metadata, geometry-only comparisons or a new consumer-side validation wrapper.

Evidence: code trace; existing C++ consumers currently construct matching views in the inspected paths, so this is a public shared-API consistency hole rather than a demonstrated GUI failure. Regression: two metadata versions sharing one geometry with distinct scale bindings; mismatched pair must reject, matching current and retained-exact pairs must materialize correctly.
