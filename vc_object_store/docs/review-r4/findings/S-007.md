# S-007: Installed CMake package omits exported static-library dependencies

Priority: P2. Baseline: `2b5d1e01fd26f27b3410d1b024c3f10a73533287`. Status: code-traced installed-package configuration; no install/build reproduction executed.

`vc_object_store/src/CMakeLists.txt:113` links `vc_objects` privately against `zstd::libzstd`. The top-level build creates that alias for `PkgConfig::ZSTD` when needed. For the default static libraries, CMake retains this private dependency in the exported link interface. However, `cmake/vc_object_storeConfig.cmake.in` only creates `PkgConfig::ZSTD` and never recreates `zstd::libzstd`. A fresh consumer doing only `find_package(vc_object_store CONFIG REQUIRED)` cannot resolve the target unless some unrelated dependency/project happened to define it first.

The same package exports `vc_object_server` (enabled by default), whose static interface retains `Boost::headers`, but the package config does not call `find_dependency(Boost 1.74 CONFIG)`. This is one installed-package dependency-closure issue, not a second store-schema finding.

Expected/shared direction: exported library interfaces must name dependency targets that the installed package config provisions consistently. Either use `PkgConfig::ZSTD` consistently or recreate the compatibility alias in the config, and conditionally find Boost when server export is enabled. Do not depend on target definitions leaking from the source-tree superbuild.

Regression: install the default static build to a private fixture prefix, configure a separate minimal downstream project with only `find_package(vc_object_store CONFIG REQUIRED)`, and link a tiny client against the exported store/server target. Also check the shared build and server-disabled configuration. No dependency installation is required for this inspection finding.

Cross-model validation: pending.
