# S-005: Point-collection source import overflows its renumbering counter

Priority: P3. Baseline: `2b5d1e01fd26f27b3410d1b024c3f10a73533287`. Status: code-traced input-boundary defect; no runtime test executed.

`vc_object_store/src/formats/PointCollectionInput.cpp`, `collections`, initializes `nextId` from the largest parsed nonnegative int64 point ID and unconditionally increments it immediately after `collidingCollections`. A document containing point ID `9223372036854775807` is accepted by `pointId` but makes this increment signed-overflow, even when there are no collisions and renumbering is disabled. With renumbering enabled, `nextId++` inside the point loop also lacks a remaining-range check.

Expected: the common source parser must reject unrepresentable allocation or avoid allocating a new counter when no repair is required; it must not execute undefined signed arithmetic. This is not a claim that ordinary datasets approach this limit.

Shared fix/regression: checked retained-ID allocation/checked arithmetic before renumbering, rather than a second integer-ID policy. Test a single maximum-ID point without collisions, a colliding document needing a new ID after the maximum, and enough renumbered entries to exhaust the remaining range. Require a deterministic documented rejection or preserved original ID, with no overflow and no partial import.

Cross-model validation: pending.
