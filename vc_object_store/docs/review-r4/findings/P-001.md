# P-001: Lasagna discards the selected surface validity mask after coordinate transformation

- Priority: P2, correctness; code-traced, not runtime-reproduced in this inspection.
- Baseline: `2b5d1e01fd26f27b3410d1b024c3f10a73533287`.
- Locations: `lasagna/stored_surfaces.py:139–148`, `lasagna/tifxyz_io.py:76–92`, `lasagna/approval_inpaint.py:61–62,94–103`.

## Reachable trigger

Read a valid stored surface through a registered affine into the fitting volume, with a valid vertex mapping to a target coordinate having a component exactly `-1`. For example, a canonical point `(1,2,3)` under an X translation of `-2` becomes `(-1,2,3)`. The canonical point satisfies the store validity rule; the transformed view carries its valid mask independently of transformed coordinates.

## Actual versus required

`TransformedGeometryView::readTile` retains source validity while applying the affine (`src/geometry/GeometryViews.cpp:314–330`). `readSurfaceGrid` and Python `SurfaceGrid` return that mask alongside target-frame points. `StoredSurface` keeps points but drops `grid.valid`. `load_tifxyz_mesh` then reconstructs a mask with `(xyz_t != -1).all(...)`, rejects this valid transformed point, and zeroes it. `ApprovalSurface.valid` repeats the same target-coordinate test for stored approval surfaces. This introduces holes in a surface accepted by the shared reader, changing fit/inpainting support.

This is not a claim that canonical single-component `-1` coordinates are valid: they are explicitly invalid in `geometry::validSurfacePoint`. The failure is reapplying the canonical sentinel convention *after* a supported arbitrary affine, instead of preserving the shared selected validity result.

## Shared fix direction and regression

Carry the shared validity mask through `StoredSurface` and its mesh/approval consumers. Do not create another placement or geometry reader. Test local and referenced stored surfaces transformed so a source-valid point maps to a target component of `-1`, with an actually invalid neighboring point; both fitting and approval paths must preserve the same mask as `SurfaceGrid.valid`. Existing positive-coordinate examples do not exercise this boundary.
