# S-001: remote surface staging silently omits supported auxiliary channels

Priority: P2 candidate. Baseline `2b5d1e01f`. Evidence: code trace, not runtime reproduced; independent adjudication pending.

Locations: `vc_object_store/src/formats/RemoteSource.cpp:17–23`; `src/formats/SurfaceInput.cpp:72–85`. Reachable through `geometry/GeometryIngest.cpp:164–169` and catalog fetching in `catalog/CatalogStore.cpp:237`.

Trigger: ingest/fetch a remote tifxyz containing a supported extra TIFF channel, such as `ink.tif` or normals, alongside its coordinates. The local importer enumerates all TIFF channels, validates their resolution/type and stores them. Remote staging downloads only meta/x/y/z/mask, then passes that incomplete directory to the same importer, which cannot know that the other channels existed. The operation succeeds with fewer arrays than the equivalent local import.

Expected: preserve explicitly advertised supported channels, or make the remote-import capability restriction explicit and reject a request requiring omitted data. Do not silently imply a complete geometry import. Arbitrary HTTP directory enumeration may not be available; an advertised channel manifest or shared reader capability is needed, not a consumer-local filesystem workaround.

Related risk, not separately counted: the optional mask download treats every `HttpClient::get` false return as absence. Check whether transport failures and not-found are distinguishable before permitting a failed mask request to change validity semantics.

No production changes. The different-model review must check whether remote coordinate-only import is an intentional documented contract, and whether this is actionable data loss rather than an accepted capability limit.
