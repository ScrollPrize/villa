# S-006 adjudication

Disposition: **confirmed, with output-layout qualification**. Severity: **P1 (destructive path collision)**. Independent source review at `2b5d1e01fd26f27b3410d1b024c3f10a73533287`; no destructive/runtime reproduction.

`apps/vc_object_import_afv.cpp:327–330` protects only the main output from pre-existing paths. After `importNative` successfully publishes its result, lines 348–349 open the independent configured report using a default truncating `std::ofstream`, with no input/output/alias comparison. `imports/AfvSource.cpp:42,189` opening AFV/AFC read-only does not prevent that separate stream from truncating those files. A report path equal to an existing source or constraint file therefore destroys original input after an otherwise successful import, and can still return success once JSON is written. This justifies P1 despite requiring a mistaken or aliasing report path; it is irreversible input destruction, not merely failed reporting.

Qualify the destination example: `InitialImport.cpp:153,163–176` uses a file for one plain shard or a packed collection, but a directory for multiple unpacked shards. `report == output` truncates the former; the latter ordinarily fails to open the directory rather than destroying it. A report naming its `collection.vcobj` or another backing member remains destructive. The source-file collision is independent of this layout distinction.

Reject protected path/alias overlaps before expensive work, use shared collection-closure protection for vcobj backing files, and publish the report safely. Whether unrelated existing reports may intentionally be overwritten is a separate CLI policy choice; universal no-clobber behavior is not needed to establish this finding. No duplicate among current findings.
