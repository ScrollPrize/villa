Disposition: **confirmed**. Severity: **P2 (public C++ API)**. Independent source review at `2b5d1e01fd26f27b3410d1b024c3f10a73533287`; no runtime reproduction, and no in-repository production caller found.

`ObjectCopy.cpp:56–61` runs `upsertObject` followed by `putGeometry` without an enclosing savepoint. `objects/ObjectCopy.hpp:21–22` exposes this composite operation inside the caller's write transaction. A valid object record plus invalid geometry makes the first operation succeed and the second throw; catching that error and committing the caller transaction retains the insertion/metadata mutation. Primitive-local rollback cannot undo an already completed sibling operation.

Unlike C-005's mismatched read-input proposal, this violates an explicit repository contract: public composite writes roll back the entire operation even when their caller catches errors and commits. Invalid geometry must fail atomically, not be trusted input. Wrap the complete helper in shared savepoint/bookkeeping handling and test commit-after-catch. The lack of GUI callers limits practical exposure, not the public atomicity requirement. No duplicate among current findings.
