# FM-C01 — GUI point JSON duplicates a weaker native decoder

Older omission present at `0c7e4e521`. `volume-cartographer/core/src/StoredCollection.cpp::storedCollection` converts point-map keys with `std::stoll` and inserts into a numeric-keyed `std::map` without checking insertion. It accepts partially numeric keys and silently drops colliding numeric identities. Runtime probes: keys `'1'` and `'01'` become one point; `'1junk'` becomes ID 1.

The native import decoder in `vc_object_store/src/formats/PointCollectionInput.cpp` already decodes the same points-map representation with full-consumption/nonnegative integer validation and collision rejection. The application adapter has duplicated only part of that interpretation, with different correctness guarantees. Its callers are `PointCollectionSync::flush` and `SurfaceCorrections::toStore`; normal generated canonical GUI keys do not trigger the malformed-input counterexamples. Standalone PointCollections JSON loading also uses permissive `stoull`; its UI/source-format responsibilities should be checked when extracting the shared point-map decoder rather than blindly replacing every file import.

Extract the common native decoding of point IDs/XYZ/annotations and use it at these boundaries, preserving legitimate per-document collision/renumbering and application-specific metadata policies. Do not call a file importer through a temporary file or duplicate its validator. Root source/runtime confirmed. The independent C++ lane was informed but terminated at its usage limit before adjudicating this candidate.
