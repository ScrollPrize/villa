# FM-C02 — Native fit-input comparison ignores saved object references

Older omission present at `0c7e4e521`. `volume-cartographer/apps/VC3D/SpiralStoreInputs.cpp::sameStore` validates saved relationship references, but `manifestPins`/`objectPin` do not validate the corresponding saved object references, including the outer shell. Missing, incomplete, wrong-object or duplicate saved object membership can proceed to current-UUID comparison/display. Python `validated_manifest_references` rejects the same malformed provenance.

Runtime probe using the existing native fit-input fixture: a valid manifest is unchanged; erasing every object `reference` still returns unchanged, and replacing each with an incomplete reference naming another object also returns unchanged. These are ingress-validation mismatches, not proof that valid current-input comparison should instead render historical geometry. Current-head content comparison remains intentional; the full saved reference must be validated at ingress without inventing another handle or requiring unavailable old payloads merely for validation.

Use shared native full-reference codecs and shared manifest object-membership validation across native/Python ingress, retaining domain-specific consumed-content projections separately. Test missing/malformed/wrong-object, duplicate objects and outer shell, partial refresh and valid stale-but-comparable manifests. The C++ Astra lane identified this candidate before hitting its usage limit; root independently reproduced it. That lane did not complete a final adjudication document.
