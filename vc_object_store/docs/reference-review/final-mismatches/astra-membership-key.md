# FM-A02 — Mixed graph-membership keys remain an internal alternate handle

Baseline: HEAD `153c9a10f1cca90f57a2e70dc5458d1bd5bad2a4` plus current post-fusion diff. **Simplification/representation candidate only; no supported collision demonstrated.** The expression exists at `0c7e4e521:src/History.cpp:988`, so it is not a latest-diff regression.

`ObjectStore::relationshipsAtSelected` uses string keys throughout `memberships`, `versions` and `currentOnly`. Archived membership starts with relationship revision UUID strings; current-only bindings synthesize a JSON array string `[edge UUID, generation, version]`, omitting owning store, although each binding already has a complete `RelationshipVersion` from `reference()`. The chosen key doubles as membership identity and a branch discriminator for whether the final record comes from `currentOnly` or `relationship(db, archiveUuid)`.

Storage archive-row UUIDs are legitimate physical locators; this is not a proposal to rewrite v21 storage. The opportunity is to resolve physical membership once into retained selected relationship values and use the shared complete publication reference for in-memory dedup/comparison. Avoid another string codec or tuple. Preserve endpoint applicability, per-endpoint membership and root/reference precedence.

Counterexample status: omitting store creates a theoretical same-generation/version owner collision, but collection shadowing and per-endpoint `seenBindings` constrain which alternatives reach this state. This review has **not** established a valid supported topology that produces an incorrect answer or duplicates one publication. Therefore do not label this a correctness defect or demand a redesign on that basis. Native history-on/off storage handling can legitimately differ; a cleanup must reduce the alternate handle logic without erasing those retention distinctions.

Siblings: `ObjectStore::relationshipsAt`, `StoreReader::graphReadViewAt/Around`, local/hosted/session selected-input capture all consume this implementation. Any accepted refactor must compare unchanged results across current-only and retained history, referenced overlays and differing endpoint owner combinations. No runtime checks in this pass.
