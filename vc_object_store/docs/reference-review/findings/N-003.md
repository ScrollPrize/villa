# N-003 — Surface history splits a reference across GUI roles

Status: candidate for independent adjudication; source-traced at `38c72d972`, not runtime-tested.

`volume-cartographer/apps/VC3D/SurfacePanelController.cpp:654–657` stores a history revision's numeric version, generation and owner in three independent Qt item roles (and its archive UUID in another). The `selected` closure at lines 668–672 reconstructs `ObjectVersion` from those roles plus the separately captured object `id`.

Producer: `StoreReader::objectHistory` returns selected `ObjectRevision` entries. Both sibling actions consume the reconstruction: View calls `_catalog->open(id, version)` then activates the resulting surface; Restore calls `restoreRevision(id, *selected(), ...)`, which publishes a source-reference restore. `SurfaceCatalog::open` and `restoreRevision` already accept the shared reference, so the intermediate spread is unnecessary. It is not an external IO boundary.

Simplification: keep the complete `revision.reference()` or selected revision as the item's data (registered Qt metatype), or keep a typed backing vector indexed by the row. Both actions should retrieve that unchanged value. Remove role-by-role reconstruction; retain display metadata separately. No schema change or JSON encoding is needed.

Validation needed: View and Restore of local/inherited historical states; same object/version but different source owners or generations; deleted overlay with retained source; selection changes. Existing surface catalog tests exercise downstream selection but do not by themselves cover Qt row transport; this review ran no GUI tests.
