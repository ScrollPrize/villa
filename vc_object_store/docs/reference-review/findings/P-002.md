# P-002 — Spiral pins maintain parallel partial and complete identities and reconstruct legacy references during internal reads

Baseline `38c72d972`; confirmed structural contract violation, existing omission. Source review only.

## Sources and closure

`spiral-fitting/object_store_inputs.py:159` `InputPins` retains both `objects: {UUID:number}` and `references: {UUID:standard reference}`, plus position store/generation. `from_provenance:191` and `from_manifest:202` preserve both representations. `refs:222` reconstructs a reference from position plus partial map when absent, validates two parallel fields and copies every reference on reads. Legacy resolution therefore remains active in the internal exact-read API, not just input decoding.

`SelectedObjects:670` repeats `versions` and `references`; `_capture_current:751` captures selectors as UUID→version maps plus a reference side channel; `resolve_selection:791` combines these again. `InputSnapshot.pins:423` rebuilds both maps from objects; `StoredObject` around 340 holds uuid/version alongside reference and manifests both. `read_snapshot:855` calls pins.refs and shared exact reads. Link preparation around 2606–2680 submits `pins.objects` as `read_versions`, then separately repins references with `receipt_object_reference`, and updates the numeric map. `link_request:2269` carries `read_dependencies` as the number-only map beside command position; this is a command boundary but its source is still the redundant internal representation.

Actual callers are `load_fit_inputs`, `prepare_fit_inputs` in the same module, service startup/input update in `spiral_service.py`, and `fit_spiral.py`/`runners/run_single.py`; persisted resume manifests/config/provenance call the conversion methods. `_pinned_records`, `_records_at_position`, manifest comparison and outer-shell selection are sibling conversion paths. `_compared:2923` deliberately strips version evidence for content comparison; that is not an identity transport and should retain its semantic distinction.

## Compatibility and fix

Older pins/manifests are legitimate persisted boundaries, not justification for fallback reconstruction on every `refs()` call. Decode old versions once with their **recorded original single-store position identity**, then validate via the shared native scalar codec and retain one list/map of complete references. A current-owner lookup would change legacy exact semantics and is not allowed. Derive UUID, numeric display values and selection membership as needed; application record wrappers may add kind and geometry evidence, not redefine identity. Existing checked command-v2 `expected_object_references` supports complete guards without a new command API. Coordinate with the native link-command owner; do not blindly remove its concurrency checks.

Estimate 70–130 removable production lines of dual-map plumbing, conversions, repin synchronization and fallback validation; exact savings depend on shared link API work. No schema 21 changes or persistent identity tables are needed. Preserve old manifests and deliberate digest/content comparison behavior. Existing `test_object_store_inputs.py:92–118` covers owner survival and legacy pin behavior; positions/lazy-relink/hosted tests exercise other entrypoints but do not prove one representation. Future regressions must cover these siblings for inherited exact reads after override/deletion, both history policies, local/hosted and packed/sharded sources, equal-number sibling owners and legacy decode once. Runtime matrix not run here.
