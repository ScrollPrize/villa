# Independent reference adjudication

Baseline: `38c72d972`. Scope: the single versioned-reference contract. This is source review, not runtime verification. Candidate IDs are adjudicated below as the producer reviews arrive.

## Design constraints established independently

- `lasagna/stored_surfaces.py` and `lasagna/fit_service.py` introduce `(generation, version[, owner])`, split the object UUID from it, and reconstruct the standard reference later. This is an actual internal representation violation. `StoredSurface` should retain the standard reference obtained from its selected record; do not reconstruct a tuple from `SurfaceGrid` fields.
- `StoreReader::selectedObject` already owns the distinction between current UUID selection, legacy current-owner version selection, and a complete exact reference. Full-reference reads bypass current lookup; preserve that behavior after override/deletion. A missing legacy owner must never be filled from attachment identity.
- Legacy textual `vcobj:UUID@GENERATION/VERSION` and flattened external JSON remain input compatibility boundaries. Decode them once through shared native handling, resolving current-owner selection in the store layer when necessary. Do not perpetuate their shape as the internal model.
- Textual `vcobj:` output is not automatically a defect: CLI/subprocess arguments and persisted JSON are real serialization boundaries. Fit-service paths feed runner transport fields. Keep necessary serialization there; remove intermediate tuple encoding and repeated parsing within one process. Do not redesign every path-taking API merely to eliminate legitimate boundary encoding.
- `Wire.cpp` has private scalar `objectVersionJson`/`objectVersionFrom` helpers. Extract/reuse shared scalar codecs instead of adding parallel field parsers. Python binding conversion between the standard dict and native `ObjectVersion` is necessary language adaptation, not itself a forbidden alternate representation.
- Existing selected `ObjectRevision` values carry metadata and identity together. Prefer retaining these over reconstructing even a correct `ObjectVersion` from flattened fields and rereading the record.
- Do not broaden the change into schema redesign, general solver-model redesign, coordinate-policy changes, or changes in history retention. Source tracing is not evidence that legacy/exact/overlay runtime tests pass.
- A proposed shared external decoder returning `ObjectVersion` is appropriate, provided already-selected canonical dictionaries bypass it in internal calls. Full exact values (including old flat JSON with an owner) must not need a current row; reject contradictory wrapper UUIDs. Current and ownerless legacy selection should delegate to `selectedObject`. Preserve explicit rejection of obsolete revision selectors and malformed version syntax.
- `RecordResolver.hpp::versionReferenceText` is a second codec using a JSON **array**, and `receiptToJson` persists that form. It is not the standard wire dict. Preserve old receipt-array decoding at that boundary while changing new output; removing array shape alone does not close native history's internal string-reference transport violation.
- Source trace clarified that fit-service invokes `fit.main` with argv in-process. Prefer canonical reference values in config until the actual argv encoder; a CLI-shaped interface does not justify converting earlier helper-to-helper traffic to locators.

## Candidate decisions

All eight candidates accepted as existing baseline omissions, not newly introduced regressions or demonstrated incorrect-result bugs. Findings live under `findings/` beside this document. Implementation may proceed subject to the constraints below; acceptance does not mean runtime closure.

| ID | Decision and required simplification |
| --- | --- |
| N-001 | Accept. Keep one `ObjectVersion` in `PinnedObject`; keep attachment incarnation, write generation and geometry separate. Unsaved version-zero pins must remain explicitly unsaved, not pass a published-reference validator. Migrate constructors and all GUI/native consumers together. |
| N-002 | Accept. Selected graph revisions are unnecessarily serialized and resolved again. Carry selected revisions/references in graph and dependency logic. Archived revision UUIDs are storage identities, not interchangeable with object versions; decode them at the shared storage boundary. Merely changing internal array strings to object strings does not close this finding. Preserve 16/56-byte schema-21 formats and both archive-selection and exact-reference entrypoints. |
| N-003 | Accept. A typed backing vector indexed by the selected row is the smallest obvious fix; a Qt metatype is also valid. View and Restore must consume the identical retained reference, without a current-row lookup. |
| N-004 | Accept. Emit canonical reference objects; decode old receipt arrays at the receipt boundary. Preserve unchanged inherited inputs, retry/replay behavior, UUID consistency checks and the reload requirement for old receipts lacking complete references. Never synthesize receipt references from receipt ownership. |
| N-005 | Accept. Share scalar native codecs and remove duplicated interpretation. Boundary serialization is legitimate. Distinct enclosing-format validation must remain explicit: do not accidentally drop positive-version/UUID validation or silently reject formerly readable persisted legacy formats. Keep selection v1 fallback and compact v2 origin encoding. |
| P-001 | Accept. Remove tuple protocol and repeated selected-reference conversion across geometry, channels and artifacts. Decode external current/exact/legacy JSON and locator inputs through shared native handling; preserve legacy current-owner semantics. Keep canonical values until necessary external/argv serialization. |
| P-002 | Accept with correction. Remove parallel numeric/reference state and internal fallback rebuilding. **Legacy InputPins explicitly have original single-store semantics:** decode old numeric maps using their recorded position store/generation once, not today's current owner. Position-only discovery is a separate supported selection. Preserve link concurrency/membership guards and deliberate content/digest comparisons; migrate complete link dependencies with native command support rather than deleting numeric guards blindly. |
| P-003 | Accept with compatibility condition. Use one reference component beside points in project, service and new provenance. Existing ownerless materialized point snapshots cannot magically become exact references: preserve their legitimate legacy use at ingress or resolve from authoritative recorded context, never guess attachment owner. Do not abruptly reject all previously valid legacy snapshots. `write_project_umbilicus` is an additional producer dropping owner and must migrate; filename collision is not claimed as a wrong-read bug without consumer/runtime evidence. |

## Implementation and verification gate

Native owns shared scalar codecs, receipt boundaries, pins and graph/history adaptation; the root owns shared external selector decoding and Lasagna; Python lane owns Spiral pins/project models. Coordinate modifications in shared headers/bindings. No public binary ABI guarantee was established by this review; source consumers must be migrated together, and externally persisted/wire legacy inputs must remain readable. Record any intentionally incomplete N-002 closure explicitly instead of treating lower-risk codec work as complete.

Required regression evidence includes standard and legacy references, local/referenced owners, retained exact reads after overlay override/deletion, source/overlay history policies, receipt replay and absent-reference recovery, and same-number different-owner identity. Packed/sharded/hosted and GUI source/runtime coverage must be recorded honestly per finding. Review fixes separately from this baseline adjudication; no runtime tests were run by this adjudicator.

## In-progress review decisions

- Python legacy-envelope adaptation: accepted after challenging the design. At an actual external/persisted boundary, extracting application envelope fields into the standard dict and immediately invoking the shared native codec is legitimate language/format adaptation. It does not require a bespoke native implementation of every Spiral manifest schema. Native code must own reference validation; Python must not infer source ownership, normalize selected references repeatedly, or retain fallback rebuilding in internal accessors. Recorded single-store position fields are explicit old-format context, not a current-owner guess. This narrows the earlier concern about manual field mapping without weakening the prohibition on internal tuple/flattened transport.
- Flagged the new locator decoder's rejection of previously accepted leading-zero decimal versions; root reports replacement with checked decimal parsing. Flagged removal of the receipt encoder's positive-version check; native lane notified. These are fix-review issues, distinct from the eight baseline findings.
- Identified unused private archive-selection graph/relationship overloads after typed migration; asked native lane to remove these and the unused access shim, rather than retain dead compatibility adapters. Identified `versionReferenceText` used only for validation after migration; native lane reports removing it instead of retaining JSON serialization inside binary encoding.
- Late baseline sibling: `SurfaceOverlap.cpp:973` uses a flattened `(store, generation, object, version, geometry)` cache key. Accepted as the same representation violation, not a wrong-result claim. The cache should retain `ObjectVersion` as one key component beside geometry. Root/native lane notified to record and implement this additional finding rather than treating the initial eight as an exhaustive inventory.
- Production-size claims remain gated on actual final counts including new files. Shared native legacy parsing and explicit ownerless-point compatibility cost code; deleting tuples does not by itself establish a net LOC reduction. Do not compress formatting to manufacture savings.
