## Legacy removal boundary

“Legacy” is an obsolete alternative representation or execution path, not every feature whose payload has an independent format version.

- Remove runtime old transaction-command formats, numeric/full side channels, ownerless saved reference/pin reconstruction, array references, and duplicated consumer schema/identity parsers. Commands remain format 3, SQLite remains schema 21 with binary UUIDs. Current UUID discovery is not an incomplete saved exact reference.
- In `StoreReader::decodeObjectReference`, remove the ownerless numbered locator compatibility branch (`generation/version` without store) and reject incomplete persisted identity. Keep complete standard references and explicit UUID current discovery. Explicit external CLI numeric selectors may still select the current owner's history once and immediately return a complete reference; they must not become an internal saved identity API. Update docs/tests to distinguish these cases rather than testing fallback as compatibility.
- `Selections.cpp::decodeSelectionRecord` accepts version 1 by reconstructing store ownership. Remove that decoder branch and reject v1 artifacts explicitly; retain version 2 and its binary wire layout. A current selection artifact's origin table is compression at a serialization boundary, not a competing internal reference API.
- `Versions.cpp` accepts missing `object_references` in saved receipts. Remove old receipt acceptance if strict current-only decoding is required; never infer inherited ownership from numeric receipts. Crucially, an unreadable receipt can describe an already-committed request. Preserve pending draft/request identity and report recovery/reload needs; never treat failed decoding as proof that resubmission under a new request is safe. This is a deliberate compatibility break, not a data migration.
- `Project.cpp::legacyResourceUuid`, fallback scanning in `resourceForEdit`, and fallback identity substitution in `resolveProjectResourceIdentity` are obsolete alternate resource identity APIs. Remove and migrate callers to canonical creation IDs or actual stored UUIDs. Direct selection of an existing object by its stored UUID must still work; deleting an alias does not authorize rewriting stored identities or references.
- Do **not** equate `Project.cpp::sortByAdded`, `internal/RecordOverrides.cpp` and `refineLegacyCreationStamp` with an old schema reader. They preserve creation ordering for valid v21 records whose creation timestamp has second precision, including across inherited overrides and history-off roots (the R9 documented invariant). Removing their behavior silently changes ordering. Retain this valid-data normalization under an accurately named shared helper, or explicitly authorize an offline data migration/ordering change before deletion. This is an exception to keyword-based removal, not an alternate identity API.
- Keep explicit offline upstream conversion (`StoreConversion.cpp`, `migration/ConvertStore.cpp` and `vc_object_convert`) as previously required. Ordinary open must continue to reject unsupported schemas untouched. `History.cpp::metadata(..., bool legacyTextUuid)` is an undesirable runtime-layer old-storage switch: extract shared decoding so the converter owns old text-UUID SQL access and ordinary history owns only binary-v21 access. Do not copy the entire history decoder into the converter. Offline conversion must continue preserving external locators, retained history, and complete converted references.
- Keep payload-only geometry reads, source import formats, geometry format 1, draft checkpoint format 1, extensions' own format versions and change-feed pagination. Their numbers do not identify old vcobj SQLite schemas. Removing them would be an unrelated feature deletion. Payload-only views still cannot authorize inverse edits without selected metadata/mapping guards.

## Initial implementation delta review

Reviewed working-tree delta against `0c7e4e521` after implementation, source only. Three findings require correction before approval:

1. **AF-05 / high: local store lifetime is acquired after GIL release.** `python/objects.cpp::readSelectedInputs` releases the GIL before its local callable invokes `self.withRead`. `StorageBindings.hpp::withStore` then reads/copies `self.db` without the GIL. Previously `withRead<true>` copied the owning shared pointer first, then released the GIL. Another Python thread can now run `close()` while the count remains one, racing that shared pointer access and potentially resetting it between `require()` and lease creation. Acquire the local store lease under the GIL, or let local `withRead<true>` own GIL release while the common helper owns only adaptation. Hosted/session native ownership remains a separate concern, not a justification for weakening local lifetime.
2. **AF-04 / medium: position JSON coercion changes accepted input.** `internal/ObjectVersionJson.hpp::storePositionFrom` calls `get<int64_t>()` directly on `commit_sequence`. Nlohmann JSON converts fractional numbers to integer; Python previously used integer casting. A position of `N + 0.5` can silently become N, defeating strict snapshot input validation; unsigned overflow also needs explicit refusal. Share strict nonnegative integer/int64-range validation across Python and wire decoding. The local native check still correctly refuses negative/future positions, but cannot recover fractional information already discarded at decoding.
3. **Legacy receipts / high: successful submission decode failure clears pending identity.** `Versions.cpp::receiptFromJson` now throws `std::invalid_argument` for missing `object_references`. In hosted `HostedStore::submit`, this may occur after a successful transaction response. `ObjectStoreSession::sendPending` catches that type and calls `conclude(requestUuid, nullptr, "")`, erasing pending state even though the transaction may already have committed. Local replay of an existing old receipt can follow the same path. `resolvePending`'s initial `receipt()` call is outside that catch and is safe, but does not cover initial submit/replay. Distinguish undecodable committed/unknown receipt outcomes from pre-submit request rejection and retain request identity/drafts. A generic runtime error alone is insufficient for local replay because the generic catch clears local pending state too. Add boundary regressions for hosted successful-but-unreadable receipts and local saved-receipt replay.

Other reviewed decisions are implemented coherently: attribute consumers use selected facades while remaining record indexing in volume inference/materialization operates on deliberate boundary dicts; geometry construction has one payload path and selected state survives; local graph capture owns its transaction and retains inherited-position refusal; status naming is propagated through native, hosted and Python signatures; project edits use actual stored UUIDs and canonicalize through session current-object selection. Selection-v1 and ownerless locator reconstruction are removed. Creation ordering retains the shared normalization, renamed `refineCreationStamp`. `historicalDependencyMetadata` has no remaining production callers, so deleting the unused helper and text-UUID branch is preferable to the earlier proposed extraction; no converter duplication is needed.

No additional obsolete runtime compatibility branch was established in this bounded delta review. This is not a claim that a keyword search proves repository-wide removal. Independent import/checkpoint/geometry formats and dedicated offline conversion remain justified exclusions. Runtime validation is being performed by the main agent; no build/test result is claimed here.

## Corrective delta disposition

Re-reviewed all three corrections in the subsequent working tree, source only:

- AF-05 lifetime finding: **resolved in source**. Local `selected_inputs` now enters `self.withStore` with the GIL held, obtaining the shared lease before the common helper releases the GIL. Native read-transaction creation/destruction occurs under that lease; Python result conversion and lease release occur after GIL reacquisition. No double GIL release is introduced.
- AF-04 integer-coercion finding: **resolved in source**. Shared `storePositionFrom` rejects nonintegers (including booleans/fractions), unsigned values beyond int64, and negatives before conversion. Both Python adaptation and hosted selected-input request decoding use it; native local capture still validates future/stale positions.
- Pending receipt finding: **resolved in source**. Public receipt decoding wraps parse/identity failures in `ReceiptDecodeError`; `savedReceipt` routes through that same wrapper, covering local replay as well as hosted success responses. `sendPending` catches this type before the invalid-argument and local generic-error cleanup and preserves pending state. `resolvePending` likewise propagates receipt failure without resubmitting. Removed `conclude` compatibility recovery is no longer needed for decoded receipts because the decoder validates every live numeric receipt entry's full identity before returning.

No new blocking source issue found in these corrective deltas or the immediately adjacent reviewed paths. The six fusions and bounded legacy removal are approved at source level, contingent on the main agent's regression verification. In particular, exercise pending preservation at both local replay and hosted response boundaries, not merely direct decoder rejection. This disposition does not claim runtime, concurrency stress, macOS or repository-wide verification.

## AF-02 transform follow-up proposal

Approve removing `GeometryView::viewTransformedAt(ObjectRevision, target, scale)` and centralizing mapping in the existing target-only view method, optionally accepting the existing `VolumeTransforms` context. Snapshot selected/UUID conveniences can delegate through selected geometry and `std::visit`, preserving the explicit transform-context boundary without duplicate mapping or payload reconstruction.

Repository-wide call search found **four**, not one, non-definition callers of the removable typed-view overload: `src/SurfaceGrid.cpp`, `src/VolumeUmbilicus.cpp`, `volume-cartographer/apps/VC3D/SpiralStoreInputs.cpp`, and `volume-cartographer/apps/VC3D/SurfaceCatalog.cpp`. The latter three construct payload-only geometry and pass selected metadata late; migrate them to `surface(selected)` / `umbilicus(selected)` before invoking target-only transformation. SurfaceGrid already constructs selected geometry. The resulting retained identity is correct even for historical reads; SurfaceCatalog's independent current/editable guard must remain.

Constraints: compute mappings from retained selected metadata whenever available, without current-head lookup. For explicitly payload-only views, shared `objectAtGeometry` may select retained coordinate metadata, but must not install an object reference or confer inverse-edit authority. Preserve the old object's UUID/geometry UUID/metadata-complete checks and existing view freshness checks when reusing `typed(state_)`. Explicit contexts must avoid refetching transforms. Keep source coordinate validation and snapshot lifetime. This is proposal approval only; implementation delta and existing exact/historical/payload-only transform regressions still require verification.

## Final source judgement

Reviewed the implemented transform follow-up, selected-value dataclasses and new recovery regressions. **Approved at source level; no unresolved blocking findings in the reviewed delta.**

- The sole mapping implementation now lives on `GeometryView`, preserves object/geometry/metadata checks, uses an explicit transform context without fetching another, and reuses the original typed state. Payload-only transformation does not install the metadata selected by `objectAtGeometry`, so it retains no reference/write authority. Selected snapshot conveniences delegate without rediscovery. Existing geometry accessors continue checking freshness against their retained state. All four removed-overload callers are migrated; a repository-wide C++ call search found no surviving call to the removed typed-view signature. SurfaceCatalog's historical editability guard remains separate.
- `SelectedObject` dataclass equality compares the complete retained revision; `StoredObject` adds its scalar-valued frame to that equality. This restores useful value comparisons without resurrecting Mapping or parallel record/reference storage. It intentionally does not recreate Mapping's cross-type/dictionary comparison convention. The remaining metadata-only `SelectedRecord` wrapper is not made into an alternative selected revision.
- `test_receipt_recovery.py` exercises the actual failure boundaries: local durable replay reads an intentionally corrupted saved receipt, and hosted durable submit receives HTTP 200 after real commit with identity fields stripped by a proxy. Both assert retained pending request identity and successful resolution after repair; local coverage also rejects an empty reference map. These tests establish more than direct decoder rejection. They do not exercise process-restart recovery or drafts with attached geometry, so those are not claimed covered by these new cases.
- Position tests include bool, fractional, negative and unsigned-overflow inputs through the Python native boundary. Existing selected geometry tests cover metadata-only coordinate changes sharing one payload and retained exact reads after deletion.

No further relevant runtime compatibility fallback was found in this bounded source review. Dedicated offline conversion, source-file formats, payload-only reads and valid-v21 creation-stamp normalization remain explicit exclusions. The main agent owns execution results for the running approved suite; this review ran no builds/tests and makes no runtime-platform claim.

Additional wire candidate identified by the main agent: approve making `Wire.cpp::exactMetaFrom` require a string whenever `meta` is present. Its four consumer families (object revision, relationship revision, object query, edge query) receive the paired `withExactMeta` representation; accepting a parsed object there is an obsolete wire fallback that loses exact metadata text. Projected query records may legitimately omit metadata and must remain accepted. Ordinary object/edge JSON-input codecs remain unchanged. Cover malformed object-form metadata rejection in both record families and projected omission success; older cached wire records should fail explicitly, not be silently normalized. This is approval of the proposed narrow strictness change, not a claim to have reviewed its eventual implementation.
