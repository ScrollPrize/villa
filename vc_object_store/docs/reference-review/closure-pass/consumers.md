## CP-C01 — outer-shell inputs bypass incremental refresh

**Medium, pre-existing omission, not introduced by `878525dd1`.** `SpiralStoreInputs.cpp::objectPins` (lines 269–274) and public `manifestPins` (278–280) enumerate only `manifest.objects`. The shell is a separate `manifest.outer_shell` entry, decoded and read by `readFitInputs` (319–331). `SpiralWorkspace.cpp:1961` builds `_fitRecords` solely from `manifestPins`; `noteStoreChanges` (1822–1862) therefore classifies an edited shell as an “other” input instead of queuing its refresh. Even explicitly passing its UUID to `readFitInputChanges` cannot repair the result: lines 341–343 loop only normal object pins, and `applyFitInputChanges` (362–388) never replaces `outerShell`. `installFitInputChanges` (2126–2156) also processes only normal patch surfaces. `FitInputs::count(InputState)` excludes the shell, although `unchanged()` in the header explicitly includes its state.

Reproduction trace: load a valid manifest with one shell through `readFitInputs`; modify or delete that shell; call `readFitInputChanges(reader, document, {shellUuid}, {})` and merge it. The saved `outerShell.state` and surface remain unchanged. A fresh `readFitInputs` correctly reports Edited/Missing. In the real GUI an edit still yields the generic “other inputs changed” warning, so this is **not** a claim of zero warning, but its shell overlay does not follow current store data and its specific freshness state stays wrong. The native direct incremental API has the same omission independently of GUI filtering.

Fix direction: one common manifest-object enumeration with an explicit shell role, reused by discovery/full/incremental paths, plus role-aware merging/display. Do not put the shell into ordinary patch relationship fitting accidentally. Extend the existing `test_spiral_store_inputs` fixture to compare full and incremental shell edits/deletion and metadata changes; the shell is currently only tested on full load. Check local/referenced owners with both retention policies using the same store API, not another shell resolver.

Source attribution: the `153c9a10f` version already separately reads the shell in full reads and omits it from `manifestPins`, `readFitInputChanges` and the merger. The new shared manifest validator correctly validates shell identity but did not introduce this older omission.

## CP-C02 — derived-surface provenance flattens application data into a reference

**Low, contract cleanup candidate, pre-existing; no wrong geometry or lost identity demonstrated.** `vesuvius/src/vesuvius/neural_tracing/inference/infer_rowcol_triplet_wraps.py:2045`, `_StoredSurfaces.save`, persists `parameters.input = {"surface": self.loaded_source, **self.loaded_version}`. `self.loaded_version` is already the complete shared reference returned by the selected surface reader. The extra `surface` field duplicates its object UUID and creates another application-specific reference envelope. The explicit single-representation contract requires additional application data beside a reference rather than mixing it into that reference's fields.

Possible simplification: store `input: self.loaded_version` directly if `surface` adds no information, or `input: {reference: self.loaded_version, surface: ...}` if it genuinely serves a separate application role. Keep sources/new-object provenance unchanged. The same expression exists at `153c9a10f`; this is not a new regression. Astra should decide whether it warrants a final cleanup or is acceptable external-boundary decoration; the native codec still receives all four identity fields, so severity must not be exaggerated.
