## CP-CORE-01 — relationship extension reads bypass the shared reference codec

Priority: low correctness/contract inconsistency. Source: `python/ExtensionBindings.hpp:183–193`, `extension_rows_at_version`. The object branch calls `objectVersionFromJson(jsonDumps(ref))`; the relationship branch manually constructs `RelationshipVersion` using `getStr` and `getInt`. That duplicates the reference schema at a binding boundary despite the existing `relationshipVersionFromJson` implementation in `src/Wire.cpp:568` and the shared field codec in `src/internal/ObjectVersionJson.hpp`.

Concrete counterexample: take the valid relationship reference created by `tests/python/test_extensions.py::test_manual_relationship_reference`, add an extra field such as `{"unexpected": 1}`, and call `extension_rows_at_version`. The manually projected relationship branch discards that field and reads the rows. The object-extension sibling and `decode_relationship_reference` reject unknown fields through `referenceFrom`. Boolean/fractional handling also depends on nanobind casting in this branch, but the unknown-field discrepancy alone establishes the finding; no claim about a particular numeric cast is needed.

Classification: pre-existing omission, not a regression of the last fix. `git show 153c9a10f:vc_object_store/python/ExtensionBindings.hpp` contains the same constructor. Placement and history policy do not affect this pre-storage boundary discrepancy. Minimal repair: the relationship branch calls the existing shared native relationship decoder, just as the object branch does; add sibling malformed-reference tests. No new reference structure, fallback or schema change is needed.
