# BV-04: Consumer knows inherited ownership to protect graph capture

Evidence: object_store_inputs.py:843 computes inherited from each reference's store versus the input position's store, then performs two conditional store-position checks around relationships_at_versions. The consumer chooses consistency behavior based on source ownership instead of receiving a coherent selected-input result.

The checks are meaningful: endpoint versions do not freeze graph membership, and an immutable object from another owner does not name a historical root graph snapshot. Existing per-record exact reads plus relationships_at_versions do not by themselves supply the required atomic multi-read/history-replay guarantee. This is an explicit shared capability gap, not permission to delete checks.

Fix direction: put capture/replay/fail-closed policy in a shared selected graph/input snapshot API, preserving requested position and selected owners. Python consumes it uniformly for local/referenced/sharded/hosted storage. Do not merely expose an inherited flag back to consumers.

Validation needed: membership changes during capture with unchanged endpoints, historical replay, immutable dependencies, mixed history policies and hosted calls. A pinned-object holder alone is insufficient.
