# BV-03: Spiral discards selected revision types and reconstructs through sidecars

Evidence: object_store_inputs.py:547 (current_record), :675 (_records_at_position) and :704 (_pinned_records) repeatedly project selected revisions into record dictionaries plus numeric version. read_snapshot near :832 builds separate reference/revision maps; its local stored factory near :883 copies kind/name/meta/tags/fiber/track/geometry into StoredObject, taking its reference from another map.

Complete source identity is currently preserved; this is not a demonstrated owner-loss defect. It is manual reassembly of data that already arrived as one selected object, with multiple places future fields can be omitted.

Fix direction: carry the selected revision through selection/materialization and compose the fitter's frame/derived metadata beside it. Shared properties provide reference, UUID, kind/name and geometry. Do not maintain a parallel copied record and reference map. Prefer one common facade over native-selected results, not another per-consumer format. Preserve explicit current/historical selection semantics.

Validation needed: selectors, current discovery, exact pins, outer shell, missing geometry, metadata-only changes and referenced/history-off inputs. Callers must retain the actual loaded identity, not a later head.
