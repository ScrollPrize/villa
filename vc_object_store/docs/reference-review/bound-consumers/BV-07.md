Evidence: lasagna/fit_service.py:679 (_stored_corr_points) receives collections with reference from shared documents.point_collections/native collectionsToPy, but returns only source/name/UUID/point dictionaries. _body_with_resolved_job_spec puts data into resolved_cfg, while _job_spec_ near :1071 retains original cfg/model selectors and is written into the checkpoint near :2062. No shared selected-input collection follows the job through materialization and saved provenance.

Actual coordinate data may remain reproducible in the resolved configuration, but UUID alone cannot identify which source revision supplied it. Current discovery at job startup is legitimate; retaining only the unresolved request afterwards is not equivalent to retaining the selected result. This is not a claim of a wrong geometry read.

Fix direction: keep the selected reference beside every resolved correction/model/surface input and preserve it through checkpoint provenance. Derive format-specific point dictionaries from that value. Share source extraction with BV-06, not another job-spec reference format or current-head read during export. Preserve original user configuration separately for display/rerun intent.
