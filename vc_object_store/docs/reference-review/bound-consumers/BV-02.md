# BV-02: SurfaceGrid callers rebuild identity already contained in the value

Evidence: native objects/SurfaceGrid.hpp carries record, version and generation; Python vc_object_store/surfaces.py:19 mirrors these but exposes no complete reference. The record already carries its actual owning identity. Lasagna stored_surfaces.read_surface retains a separate input reference beside the grid; StoredSurface copies geometry identity/channels into another wrapper. Vesuvius neural_tracing/inference/surface_store.py:21 manually calls object_reference(grid.record).

Fix direction: let the existing shared loaded-surface value expose its derived complete reference, and retain that value beside format-specific data. Remove consumer reconstruction/redundant identity state, not coordinate conversion. Do not add persisted identity or replace the canonical reference dictionary. Immutable channel payload keys are not themselves a bug.

Classification: consolidation/API omission, not a demonstrated wrong read. Not every wrapper can disappear: Lasagna deferred channels and Vesuvius tifxyz/ZYX adaptation have real requirements.

Validation needed: selected owner preserved after overlay/deletion, coordinate metadata edits sharing geometry, deferred channels and unchanged canonical reference transport.
