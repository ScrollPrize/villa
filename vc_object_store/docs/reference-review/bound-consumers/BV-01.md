# BV-01: Selected geometry is not uniformly available through the value API

Evidence: vc_object_store/include/vc_object_store/store/GeometryViews.hpp:28 already defines GeometryView::reference(), but python/TypedGeometryBindings.hpp:145 exposes only revision and numeric version. Native typed factories at GeometryViews.hpp:166 accept UUID plus optional geometry revision, not a selected ObjectRevision/ObjectVersion, although transformed views have a selected-revision overload.

Caller trace: FiberCollectionController.cpp:763 resolves a full reference, extracts UUID and geometry revision to construct a fiber view, then supplies the selected object again for transforms. Python users must separately retain/extract a record reference because the view cannot return it. This is repeated glue caused by API gaps, not evidence that its checks should be deleted.

Fix direction: expose the existing native reference in Python and extend existing factories to accept selected state directly. Resulting views retain its metadata/reference automatically; raw payload-only views remain explicitly payload-only. Consumers pass the selected value, not a new tuple of UUID/geometry/version. Never manufacture a reference from view.version or attachment ownership.

Validation needed: retained exact views, metadata-only coordinate changes sharing geometry, referenced owners, override/deletion and payload-only views with no object identity. Source review only.
