# BV-05: Editable point collections split selected state from editable data

Trace: SpiralWorkspace::rebuildFitPclDocuments serializes a full reference into metadata. EditablePclDraft (SpiralPointCollectionEdit.hpp:36) stores JSON but has no typed selected-reference component. SpiralStoreEdits::setPointCollectionObject writes reference/UUID into JSON; savePointCollections at :137 decodes it again and separately checks UUID agreement. Serialization is a real document boundary, but a loaded draft should not reinterpret identity at every save.

Sibling flow: PointCollectionSync loads AttachedCollection values already carrying reference and mapping, splits them into revisions_ and mappings_ (PointCollectionSync.hpp:59), then reconstructs state in flush and advances it from receipts. The controller genuinely handles editing/freshness; not all its version logic is redundant.

Fix direction: decode once at ingress; keep editable collection and typed selected reference/mapping together and use shared checked collection-write/receipt handling. Preserve UI IDs, new-object IDs, stable point-ID allocation and deletion states. AttachedCollectionsSnapshot has owner/role membership semantics; standalone volume collections need a shared equivalent/generalization, not a copied implementation.

Classification: consolidation opportunity with a collection-snapshot capability difference, not proof of stale writes. Validate no-ops, repeat saves, missing/retired records, inherited owners, registration and membership changes.
