## PC-S01 — stale-link scope compares raw UUID spelling with canonical stored IDs

Priority: low correctness/API consistency, independently source-confirmed by Astra. `src/linking/LinkCandidates.cpp:65–68` inserts `StaleEdgeScope.objectUuids` and `.touching` directly into string sets. The ordinary edge selection at lines 80–87 parses these IDs through the store API, so uppercase UUIDs find the same records as lowercase ones. However, lines 99–101 then compare the canonical stored endpoint strings directly to those raw scope strings.

Concrete source-level case: create a pending edge owned by detector D between canonical A/B. Call public `commitCandidates(db, D, version, {}, true, &scope)` with `scope.edgeKinds={edge.kind}` and `scope.objectUuids={uppercase(A),uppercase(B)}`. The edge is selected, but fails `scopedObjects.contains(e.aUuid)`/`contains(e.bUuid)` and is preserved. The identical lowercase scope removes it. Likewise, a nonempty uppercase `.touching` can silently prevent stale removal. Both standalone and caller-owned transaction overloads share the implementation, so one native boundary fix serves them; ordinary internally produced detector scopes are already canonical from `StoredGeometry::select`.

Classification: old omission, not a regression in the recent closure commits. The same raw insertion/comparison exists at `70da58935`. This is not a need for another reference format or per-object routing structure: normalize the public scope UUID vectors through existing `util::canonicalUuid` once at the shared native boundary, and keep edge-kind strings unchanged. No runtime reproduction is claimed here; Astra independently confirmed the source trace.
