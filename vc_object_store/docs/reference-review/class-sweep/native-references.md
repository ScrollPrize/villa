# Native reference-construction class sweep

Frozen source: `d13d33629`. Read-only source/caller sweep; no production/test edits, builds, installations or runtime claims from this lane. Scope is conversion of numeric/publication fields into `ObjectVersion`/`RelationshipVersion`, including implicit aggregate returns, field-by-field population and receipt/status reconstruction. Structural array validation and obsolete wire forms are reviewed separately by root/Astra.

## Search and closure method

Repository-wide native files (`*.cpp`, `*.hpp`, `*.h`, `*.cc`, `*.cxx`) were searched for the two reference types and decoders, qualified/unqualified braced constructors, `PinnedObject` aggregates, assignments to `storeUuid`, `generation`, `versionStoreUuid`, `versionGeneration`, `objectUuid`, `relationshipUuid`, `selected`, `reference` and `base`, and `push_back`/`return` aggregates containing version/owner fields. Numeric receipt maps and every `reference(...)` call with arguments were searched independently; this finds construction without the type name at the call site. Tests, generated build trees, third-party/external code were excluded. Search matches were then followed through their actual producers and callers; declaration-only/type aliases and non-vcobj counters were not counted as defects.

Findings are judged by whether the complete identity already exists and is discarded, or whether the code is the legitimate boundary responsible for creating it from authoritative storage/wire/explicit input. A textual search for a numeric field alone is not proof of wrong ownership.

## Verdict

No additional confirmed **native** numeric-to-reference reconstruction defect was found in the covered call sites. The known `NX-P01` link-marker Python consumer remains a seed finding owned by the Python lane, not counted again. Its native sibling `prepareLinkObjects` already guards with the selected marker's complete `reference()` (and tombstone state).

## Exclusions and no silent omissions

- Struct declarations, optional/vector/map aliases, forwarding signatures and copying a complete ObjectVersion are not construction from a bare number. Header matches in ObjectStore/StoreReader/ObjectCollection/GeometryViews/Transactions/ManifestReferences/SurfaceGrid/VolumeUmbilicus/AttachedDocument/ObjectLinks/Spiral draft types were dispositioned accordingly.
- `ObjectIdentity` (owner+UUID) routes objects but is not an exact-version handle. Import UUID allocation, external source IDs, track ordinals, point IDs, attachment process generations, view-cache generation counters and detector version numbers were classified separately; they were not silently upgraded to complete references.
- Explicit migration/conversion materializes authoritative new publication rows and metadata; that is a storage/format boundary, not an operational consumer guessing an exact source owner. No new operational legacy reference path was found there.
- Previously accepted `ObjectCopy::copied_from` remains external provenance without an operational parser reconstructing a pin. This sweep does not broaden into rewriting every arbitrary metadata layout.
- Python **source** consumers and native nlohmann codec shape/legacy acceptance are covered by root/Astra. Native bindings' ownership-construction paths are included above. The requested additional Qt boundary sweep is recorded below; no malformed-value runtime tests were run in this lane.
- Repository-wide native type/construction search found vcobj reference consumers in `vc_object_store` and `volume-cartographer`; no matching native constructor in other repository subprojects. Dynamic/reflection-generated code and untracked external callers cannot be inferred from static search and are not claimed covered.

This is finite call-site/invariant coverage, not a guarantee of zero bugs. No runtime matrix, performance, macOS/GUI or concurrent-service validation is claimed from this source-only sweep. No fixes were applied while reviewing.

## Qt expected-list boundary sweep

The repository-wide native search yielded 115 production `volume-cartographer` files containing `vc_object_store`, `vc::objects` or `ObjectStore`. All were searched for `toArray`, `QJsonArray`, `isArray`, and reference/legacy parser spellings; 29 `toArray` call sites occur in 10 files. The associated AgentBridge method descriptors, dispatch validator, point/edit handlers, Spiral brush callers and winding-bound parser were additionally followed even where those files do not directly name vcobj. This is not a claim to audit unrelated GUI JSON, numerical algorithms, or every arbitrary metadata field.

An array is the correct schema. A defect requires an authoritative ingress to accept a non-array as valid input; an ordinary internal iteration or a conversion whose empty result is rejected is not a defect. Validation belongs once at ingress, not at every iteration.
