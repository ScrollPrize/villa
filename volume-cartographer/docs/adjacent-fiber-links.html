Adjacent fiber links

Adjacent fiber links are revisioned relationships in the object store.

Meaning

An ordinary link ties two control points to the same winding of the sheet. An adjacent link ties a vertical fiber to a horizontal fiber one winding outside it: WV = WH − 1. Effective H/V tags determine which side is inside. A link without one H and one V remains stored, is flagged in the fiber map, and contributes no winding constraint.

Storage and edits

Each link is one shared fiber_branch relationship with an edge UUID, control-point anchors, directions and approval state. Its metadata sets adjacent: true for an adjacent link. An unreviewed automatic link (the Fiber Map's “Link A and B”) sets auto: true while it is pending; approval clears it, and an adjacent link never carries it. VC3D calls the database relationship APIs in the same transaction as geometry changes. Splits create new objects, redirect affected relationships and retire the original atomically.

Display names are labels. Fiber UUIDs identify objects and edge UUIDs identify relationships. Revision expectations reject stale edits. VC3D does not repair reciprocal files or merge remote copies.

Explicit JSON transfer

Version-4 transfer documents represent ordinary links in branches and adjacent links in adjacent_branches; a pending automatic ordinary link carries "auto": true next to "pending": true. Export includes reciprocal entries for linked endpoints with the same edge UUID and UUID-based target filenames. Import validates reciprocity before committing the shared relationship. Old formats and implicit migration are unsupported.

Map and editing

Adjacent candidates and links use triangles. Created links are pending. H/V tags determine the one-turn offset, and adjacent links do not certify kollesis seams. Kind disagreements contribute no winding constraint.
