# Reference replay driver

`vc/fiber_tracer/FiberReferenceReplayCore.hpp` exposes the shared, synchronous
reference replay protocol independently of a tracing backend. It uses the
existing polyline projection, anisotropic error metric and excursion-grace
implementation rather than maintaining another evaluator.

## Contract

Build the reference with `makePolylineArcGeometry`. Supply an interval, nominal
step, trace-step budget factor, normal/tangential error thresholds and a
`ReplaySegmentRunner`. Geometry and distances are in **base voxels**; the normal
sampler's working-to-base scale is explicit. The runner receives a seed,
remaining reference distance and maximum steps. It reports each committed
point (not the seed) through the observer and must stop when that callback
returns false. It must not retain callbacks or invoke them asynchronously.

For the native extrapolator, adapt `traceFiberExtrapolation`'s committed-step
callback, converting trace coordinates to base coordinates if needed. Keep
this adapter's coordinate conversion consistent with the reference and normal
scale. The opt-in real-data test demonstrates this with a unit-scale field.

The driver matches committed points forward along the reference. Distance
failures use the shared anisotropic metric and optional excursion grace;
an unfinished excursion at termination still fails. Each failure is recorded,
and the next segment starts farther along the reference. A deterministic
segment bound prevents an unproductive backend from looping indefinitely.
Progress events carry the segment index, matched reference arc and fraction.

## Optional filtering

`ReplayConsistencyPolicy` supports point acceptance and periodic checks of
the actual forward geometry. A verifier can call `verifyFiberReverseSpan`.
Checks can cover the latest window or the complete prefix; the final partial
window is checked too. By default a distance failure is retained without
reverse filtering; `allEndpoints` also checks those terminal spans. A rejected
span rolls back to the last verified prefix, then calls `nextSeed` to restart
ahead. `seedAllStarts` additionally uses prediction-based seeds at ordinary
segment starts. Seed search must return an arc in its requested interval or
no seed when the remaining interval has no acceptable seed.

Do not equate reaching `completedReferenceArcBase` with successful tracing:

- `failures` contains ordinary distance/backend failures.
- `filteredStops` records rejected windows, detection locations and reseed arcs.
- `seedSearchSkippedBase` records additional seed-search gaps, excluding the
  mandatory restart step.
- Each segment retains only its accepted prefix; a rejected distance-failure
  endpoint is preserved separately in `filteredDistanceFailure` for auditing.

Report filtering/skipped coverage alongside restart counts. A policy that
rejects every span must not appear to trace the whole reference successfully.
Backend exceptions propagate to the caller; they are not converted into good
coverage or ordinary tracing failures.

## Validation

Using an existing configured build (no extra dependencies):

```sh
cmake --build build --target test_fiber_reference_replay_core -j 8
ctest --test-dir build --output-on-failure -R '^test_fiber_reference_replay_core$'
```

Tests cover deterministic resets, unfinished grace excursions, invalid budgets,
periodic/final reverse checks, rollback, presence filtering and seed-search
accounting. For a cache-only real-data check, set `VC_TEST_WIDTH_MANIFEST` to
an existing prediction manifest, `VC_TEST_WIDTH_FIBER` to a covered annotated
fiber JSON, and `VC_TEST_REVERSE_NORMAL_MANIFEST` to its normal manifest before
running the test executable. These fixture inputs are not downloaded or
generated by the test; without them the real-data case is skipped.

Validated with GCC 13 Release on a cached Paris4 reviewed fiber: the first
64 base voxels after the annotated start produced zero distance failures and
zero filtered stops, with two reverse checks. Serial and four-thread execution
returned identical paths; retained-point errors were independently recomputed
with the shared metric. This is an extraction/correctness check, not an accuracy
or performance improvement claim. No local macOS/arm64 validation was performed.
