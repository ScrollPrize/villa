# Native CPU training preparation kernels

`vc.volume` exposes three single-threaded CPU operations used by the Fiber3D
preparation work. This is an extraction of the existing implementations, not a
change to their arithmetic, sampling convention or augmentation distribution.
The trainer and loader do not switch paths in this change. No CUDA, Torch,
model, annotation or manager dependency is added to the native module.

All operations allocate an independently owned, contiguous NumPy output and
leave inputs unchanged. Inputs are contiguous `float32` NumPy arrays, except
the value transform's boolean statistics mask. There is no internal worker pool;
the compute loops release the Python GIL so callers can schedule independent
operations. Factories in an ordered CPU sample queue can call these bindings
without nesting a second native compute pool.

## Fused coordinates

```python
coords_zyx, valid = vc.volume.generate_fiber3d_coords(
    output_shape_zyx, cp_local_zyx, cp_volume_zyx,
    output_to_source_zyx, smooth_mode, smooth_controls,
    smooth_origin_zyx, smooth_spacing_zyx,
    volume_spacing_base, base_shape_zyx,
)
```

The output is `(Z, Y, X, 3)` float32 coordinates in **base ZYX voxels**, plus
a `(Z, Y, X)` uint8 validity array. For each integer output position `p`:

1. Apply `output_to_source_zyx @ (p - cp_local_zyx)`.
2. Apply the requested inverse smooth transform.
3. Add `cp_volume_zyx` and multiply by `volume_spacing_base`.
4. Mark valid exactly when all three resulting coordinates are finite and
   inside the inclusive base-volume bounds `[0, base_shape_zyx - 1]`.

The two CP vectors, control origin and control spacing have shape `(3,)`;
the matrix has shape `(3, 3)`. CP volume coordinates and smooth-transform units
are selected-volume voxels before multiplication by the positive base spacing.
Controls contain displacements in those same units. No random parameters are
generated by this function.

| Mode | Controls | Inverse transform, in execution order |
| --- | --- | --- |
| `none` | Empty list | Affine only. |
| `1d` | One 1D array | Subtract the X-interpolated displacement from Z. |
| `2d` | One 2D YX array | Subtract the YX-interpolated displacement from Z. |
| `3d` | Three 2D arrays: YX, ZX, ZY | Subtract ZY displacement from X, then ZX from Y, then YX from Z. |

The `3d` mode is the existing composition of three smooth shears, **not** a
general three-channel 3D displacement field. Each lookup uses coordinates
already updated by the preceding inverse shear. Controls use clamped linear
or bilinear interpolation; singleton axes are supported. Applying three
displacements independently at the original coordinates would change the
transform and is not equivalent.

Dimensions, shapes, finite parameter/control values, positive spacing and
allocation arithmetic are checked before allocation/computation. Coordinate
validity says nothing about missing CT chunks; use the sampler's returned
coverage separately. Keep supplied transforms within a numerically meaningful
float32 range.

`Volume.sample_coords` takes **XYZ**, unlike this binding's ZYX output. Flatten
the leading dimensions into a coordinate image, reverse the last axis and make
that array contiguous before passing it to the native sampler. Convert the
validity image to boolean. This layout conversion does not change the coordinate
values or the sampler's interpolation policy.

## Oriented CPU blur

```python
filtered = vc.volume.anisotropic_blur_3d(
    volume_zyx, axis_zyx, sigma_along, sigma_across,
)
```

`volume_zyx` has shape `(Z, Y, X)`, and `axis_zyx` is a finite, nonzero vector.
The function normalizes that vector and constructs two perpendicular axes.
It performs one Gaussian pass along the supplied axis, then one along each
perpendicular axis, using the same across sigma for both. Sigmas are finite,
nonnegative and measured in input-array voxels; zero skips that pass. If all
passes are skipped, an independent copy is still returned.

Each 1D kernel has radius `max(1, ceil(3 * sigma))` and is normalized to unit
sum. Axis-aligned passes use a direct line convolution. Other passes precompute
the existing trilinear oriented-tap stencil and merge coincident offsets.
Sampling beyond the input replicates its edge values. Interior application
reuses linear offsets without repeating boundary checks per tap.

This is the existing **three-pass CPU filter**. It is not a replacement for the
later GPU direct-formula rectangular convolution and should not be described as
bit-identical to that different filter. No GPU convolution grouping or sampling
recipe is transferred here. Use finite image values and practical augmentation
sigmas; this API is not intended for unbounded kernel radii.

## Fused value transform

```python
image = vc.volume.fiber3d_value_transform(
    volume_zyx, valid_mask, normalization, contrast, brightness, gamma,
)
```

The input image and boolean mask have identical, nonempty `(Z, Y, X)` shapes.
Supported normalizations are `none`, `raw`, `identity`, `zscore` and `minmax`.
`none`, `raw` and `identity` are aliases. Z-score uses population variance and
a minimum standard deviation of `1e-6`; min/max uses a minimum range of `1e-6`.
Statistical sums use the existing double accumulation with float32 means,
divisors and output math. Contrast and gamma must be finite and positive;
brightness must be finite.

The transform order is:

1. Calculate statistics from mask-selected values.
2. Normalize the full image.
3. Apply contrast about the normalized selected mean, then brightness.
4. If gamma differs from one, map the selected min/max range to `[0, 1]`, clamp,
   apply gamma and map back to that range.

The mask selects **statistics only**; masked-out pixels are also transformed,
not zeroed. If the mask selects nothing, normalization is bypassed and the whole
image supplies the subsequent contrast/gamma statistics. This preserves the
legacy contract. Callers which already zero-fill missing samples can reuse an
all-valid mask; the API does not require introducing mask transport. Image
values supplied by the caller must be finite.

## Build and validation

Use an already configured build with the native Python prerequisites described
in the [source-build instructions](../README.md#python-source-builds):

```bash
cmake --build build/pr-native --target vc_volume -j 8
python -m pytest -q python/tests/test_native_training_kernels.py --vc-build-python build/pr-native/python
```

The explicit build argument prevents an editable installation from silently
testing a different checkout's binary. The tests use independent NumPy
coordinate, oriented-interpolation and statistics references; they also check
edge handling, invalid arguments, repeated determinism, shape/dtype/ownership
and input immutability. Float32 references allow only their documented rounding
differences; the extracted C++ operations themselves are unchanged.

Supply a local CT array via `--vc-real-volume`, an occupied base XYZ crop via
`--vc-origin-xyz` and the selected `--vc-level` to run a real-data chain:
inverse warp, native sampling, oriented blur and value transform. Tests never
download data, change the volume, acquire a GPU or start training. The companion
`test_native_sampling.py` suite checks exact sampler fast-path equality and
offers a real-volume timing check. Extraction alone makes no new throughput or
model-quality claim.

Extraction validation on Ubuntu/Python 3.14 passed 86 native binding/sampling
tests and the companion 27 ordered-queue tests. On a 128³ Paris4 CT patch,
coordinates, validity, oblique blur and transformed values also matched an
existing source binary byte-for-byte (GCC 11 Release reference versus GCC 13
Release extraction). A Clang 14 syntax check passed; macOS/arm64 runtime
validation remains pending.
